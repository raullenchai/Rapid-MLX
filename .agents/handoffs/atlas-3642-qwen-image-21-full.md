# Qwen-Image 2.1 integration handoff

- Receiving role: Atlas for feature integration; Vector for real memory measurement; Harbor for candidate artifact dogfood and release documentation.
- Integration branch: `feat/3642-qwen-image-21`, merged through PRs [#3649](https://github.com/raullenchai/Rapid-MLX/pull/3649) and [#3652](https://github.com/raullenchai/Rapid-MLX/pull/3652). Follow-up cache fix: `fix/3642-shared-hf-blobs`, [#3659](https://github.com/raullenchai/Rapid-MLX/pull/3659). Tracking issue: [#3642](https://github.com/raullenchai/Rapid-MLX/issues/3642).
- Verified from the published mflux 0.20.0 wheel: `QwenImage21` uses `ModelConfig.qwen_image_21()`, defaults to 40 steps and guidance 1.0, accepts one `image_path` with `image_strength`, and keeps the Qwen3-VL text encoder bf16. The official HF revision `790c92633540aa0cb11d9abf19eb46d861714758` has `model.language_model.embed_tokens.weight`; its weight/tokenizer download footprint is 33,131,596,301 bytes. The mflux import succeeds with the Desktop torch-deferral patch in a no-torch scratch install.
- This branch wires the distinct family, pinned download, Qwen3-VL encoder guard, q8-on-load, MemorySaver with tiled VAE, new-prompt reload after encoder eviction, single-image img2img, catalog/admission, docs, and Desktop sidecar pin/import. Independent review found and fixed a blocker in the shared download gate: the official 2.1 layout uses `processor/tokenizer.json`, a Diffusers transformer index, and a single-file VAE, unlike existing mflux packs. A pinned-layout synthetic cache test now covers completeness and a missing transformer shard. Focused Python and Swift tests passed. See the PR for exact test commands and CI result.
- Real-weight evidence: the official pinned snapshot was downloaded to the Mac mini's shared HF cache. The first Server load failed because its valid two-link shared blob layout was rejected as incomplete; PR #3659 fixes this with narrow ownership and shared-blob path-layout checks plus adversarial tests. On an M2 Pro/32 GB machine, the fixed source environment returned HTTP 200 and valid 1024-square PNGs through both Server image endpoints. Direct engine generation and img2img also completed at 512-square. Timings, visual results, and limitations are in [the dogfood note](../../docs/engineering/performance/2026-09-21-qwen-image-2.1-dogfood.md). The separate Bonsai service remained alive.
- Unresolved release evidence: these runs used editable source with pre-existing swap and another resident model. They do not establish a clean 32 GB memory floor or qualify a release wheel/Desktop sidecar. An exact-candidate cold start, default generation, warm rerun, offline restart, cancellation recovery, total unified-memory peak, and real Desktop journey remain outstanding. Img2img preserved composition but did not reliably follow color/style instructions; this is the upstream img2img mode, not the separate instruction-edit variant.
- Next action for Atlas/Harbor/Vector: merge PR #3659 after exact-head checks and review, then run the [release dogfood matrix](../../docs/engineering/operations/image-release-dogfood-matrix.md) against the built candidate. Measure unified-memory peak and swap with no other resident model; if the 32 GB floor fails, adjust alias admission and minimum before release. Harbor should keep the matrix row unqualified until its exact-candidate checks pass.
