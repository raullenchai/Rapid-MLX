# Інструкції для Codex

- Відповідай українською.
- На цій машині dev/test оточення працює через Nix, або що завгодно що потребує додаткових пакетів/програм.

## Валідація змін

- Після будь-яких змін у репозиторії перед фінальною відповіддю локально провалідуй їх через Nix.
- Для PR-змін завжди запускай повний `pr_validate` без `PR_VALIDATE_NO_CODEX`, без `--skip-steps` і без інших скорочень, щоб обов'язково виконувалися `codex_review`, lint, targeted tests, full unit та решта кроків:

  ```bash
  nix develop path:/Volumes/SRC/Rapid-MLX --command python -m scripts.pr_validate.pr_validate <PR_NUMBER> -v
  ```

- Для непіарних змін запускай найближчу повну локальну валідацію, яка відповідає зміні; якщо зміна може піти в PR, використовуй повний `pr_validate`.
- Не пиши, що зміни перевірені, доки не маєш локального результату. Якщо повна валідація неможлива або користувач явно просить її не запускати, у фіналі назви точну причину, команди, які були виконані, і що залишилося неперевіреним.
- Якщо failure виглядає як проблема локального середовища або pre-existing base failure, перевір базу/артефакт, вкажи точний шлях до артефакту і не ховай failure.
