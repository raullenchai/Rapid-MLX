Rapid-MLX 0.15.3 adds supervised Computer Use for local Mac tasks and a
documented API for clients that provide their own interface. It also improves
first-run setup, model serving, and recovery from common startup errors.

## Experimental Computer Use

Computer Use remains an opt-in experimental Desktop feature. It can run
supervised tasks in a selected macOS app or browser window, shows consequential
actions for approval, and stops when its target or approval context changes.
Credentials, payment details, and commerce actions are blocked.

Expect incomplete tasks: local planners can stop early or loop on longer work,
browser URL verification requires macOS Automation permission, and changing or
obscured windows can end a run. Review every approval prompt and be prepared to
finish the task manually. The local control API requires authentication;
screenshots stay disabled unless both the server and the request opt in.

## Highlights

**Give Rapid a task and let it find the right app.** The Desktop
Computer Use panel starts with your task, then resolves a bounded scope
from open apps and windows. When several choices fit, Rapid asks you to
choose; the active scope stays visible while the task runs. Add or select
a local or HTTPS OpenAI-compatible planning Model directly in the panel,
then follow progress and approve consequential actions. The Computer Use service starts without
loading a chat model. Screen Recording belongs to the Desktop app and
Accessibility to its bundled helper. Browser tasks may ask macOS to let the
Desktop app control the browser before Rapid proposes a scope; if access is
unavailable, Rapid explains how to retry. The local action-outcome ranker is
advisory: if it cannot be reached, the task can continue without treating an
unverified action as success. Runs remain limited to the resolved or
approved app and website scope.
([#3909](https://github.com/raullenchai/Rapid-MLX/pull/3909))

**Build your own Computer Use client.** An authenticated `/v1/cua` API exposes
capabilities, permission state, app and window discovery, bounded observations,
run creation, event polling, approval decisions, and cancellation. A client can
use the model-free `--cua-only` server mode. Screenshots are disabled unless
both the server and the request opt in; raw click and typing operations are not
exposed through this API. Sessions are process-local and end when the server
restarts. ([#3909](https://github.com/raullenchai/Rapid-MLX/pull/3909))

**Run Qwen Image 2.1 on Macs with less free memory.** The image path now
supports lower-memory configurations without requiring a larger machine for
every generation. Actual fit still depends on the model and the memory
available to the process.
([#3762](https://github.com/raullenchai/Rapid-MLX/pull/3762))

**Get started and recover more easily.** Running bare `rapid-mlx` now shows
first-run guidance. Missing optional runtimes provide install commands that
match the active install method, and the server gives clearer failures for
missing local paths and curated model IDs.
([#3861](https://github.com/raullenchai/Rapid-MLX/pull/3861),
[#3831](https://github.com/raullenchai/Rapid-MLX/pull/3831),
[#3863](https://github.com/raullenchai/Rapid-MLX/pull/3863))

**More predictable agent requests.** Strict structured output now works with
streaming and tool calls while keeping completion budgets within the model
context. QuickSilver prompt admission and hybrid checkpoint caching have
additional bounds to keep long sessions stable.
([#3871](https://github.com/raullenchai/Rapid-MLX/pull/3871),
[#3908](https://github.com/raullenchai/Rapid-MLX/pull/3908),
[#3835](https://github.com/raullenchai/Rapid-MLX/pull/3835),
[#3836](https://github.com/raullenchai/Rapid-MLX/pull/3836))

**Rejections explain the capability boundary without exposing request text.**
A `capability_rejected` response can now include a closed `reject_reason`
for structured-output and context-length rejections. The field uses only
approved values, with no free-form error details.
([#3871](https://github.com/raullenchai/Rapid-MLX/pull/3871))

Blank PDF pages now bypass text recognition, so importing a scanned PDF with
blank pages can finish or report that no readable content was found without
waiting on OCR for those pages. Nonblank pages still use text recognition.
([#3911](https://github.com/raullenchai/Rapid-MLX/pull/3911))

Inference failure telemetry uses closed categories; private error text and
Computer Use observations are not sent as telemetry.
