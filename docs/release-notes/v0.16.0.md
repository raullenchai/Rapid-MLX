Rapid-MLX 0.16.0 expands packaged multimodal and local decision workflows, adds guarded accelerated model profiles, and improves long-running server, agent, cache, and Desktop reliability. Performance varies by model, hardware, and workload; this release makes no general throughput or coding-quality claim.

## Highlights

- **Vision, image, and video runtimes in the base package.** The packaged runtime now includes the dependencies used by supported vision understanding, image generation, and video generation flows, with a documented video workflow. Model-specific weights and capability checks still apply; inclusion of a runtime does not make every model or modality supported. ([#4309](https://github.com/raullenchai/Rapid-MLX/pull/4309))
- **Local typed decisions.** System One can serve Decider and native MLX Clef models for structured answers and candidate ranking. Native Clef supports its validated image and video inputs. OpenJev adds text-only answer and rank decisions from the pinned published conversion or an explicit local conversion; its published weights are CC BY-NC 4.0 and are restricted to non-commercial use. ([#4341](https://github.com/raullenchai/Rapid-MLX/pull/4341), [#4365](https://github.com/raullenchai/Rapid-MLX/pull/4365), [#4374](https://github.com/raullenchai/Rapid-MLX/pull/4374))
- **More guarded accelerated profiles.** Bonsai 2 27B, Gemma 4 26B, and DeepSeek V4 Flash gain experimental TensorFold profiles. Related fixes preserve conversation boundaries and follow-up state, apply requested sampling, keep thinking-disabled answers in content, and return actionable client errors for requests the profile cannot serve. Each profile keeps its shipped model, runtime, hardware, and capability guards and fails closed outside them. ([#4289](https://github.com/raullenchai/Rapid-MLX/pull/4289), [#4301](https://github.com/raullenchai/Rapid-MLX/pull/4301), [#4308](https://github.com/raullenchai/Rapid-MLX/pull/4308), [#4310](https://github.com/raullenchai/Rapid-MLX/pull/4310), [#4314](https://github.com/raullenchai/Rapid-MLX/pull/4314), [#4317](https://github.com/raullenchai/Rapid-MLX/pull/4317), [#4319](https://github.com/raullenchai/Rapid-MLX/pull/4319), [#4323](https://github.com/raullenchai/Rapid-MLX/pull/4323))
- **More reliable shared prefixes and streaming.** Multi-turn and multimodal requests retain reusable prompt boundaries, concurrent matching prompts can wait for an in-flight prefill, divergence snapshots are stored at the correct boundary, and automatic prefix-cache persistence is coordinated across server processes. Streaming receives a bounded scheduling opportunity during another request's long prefill, and streamed tool arguments remain byte-consistent with buffered JSON. These are correctness and responsiveness controls, not a universal speedup claim. ([#4299](https://github.com/raullenchai/Rapid-MLX/pull/4299), [#4340](https://github.com/raullenchai/Rapid-MLX/pull/4340), [#4344](https://github.com/raullenchai/Rapid-MLX/pull/4344), [#4345](https://github.com/raullenchai/Rapid-MLX/pull/4345), [#4351](https://github.com/raullenchai/Rapid-MLX/pull/4351), [#4366](https://github.com/raullenchai/Rapid-MLX/pull/4366), [#4338](https://github.com/raullenchai/Rapid-MLX/pull/4338), [#4381](https://github.com/raullenchai/Rapid-MLX/pull/4381))
- **Current agent setup and protocol behavior.** Setup can finish before the local server starts and supports the current OpenCode provider and service configuration. Agent clients receive protocol-correct context-limit errors, streaming behavior is pinned across supported API protocols, and reproducible long-running daemon checks cover session stability. These checks validate integration behavior; they do not rate model quality. ([#4304](https://github.com/raullenchai/Rapid-MLX/pull/4304), [#4073](https://github.com/raullenchai/Rapid-MLX/pull/4073), [#4343](https://github.com/raullenchai/Rapid-MLX/pull/4343), [#4348](https://github.com/raullenchai/Rapid-MLX/pull/4348), [#4379](https://github.com/raullenchai/Rapid-MLX/pull/4379), [#4380](https://github.com/raullenchai/Rapid-MLX/pull/4380))
- **Operator control over model artifact downloads.** A CLI flag, environment setting, and configuration option can prevent automatic missing model-artifact downloads while preserving complete cached models and explicit `rapid-mlx pull`. An uncached model receives a typed refusal and recovery guidance. This control is not general offline mode: BYOM preflight may still query repository metadata; use the existing Hugging Face offline settings when zero Hub traffic is required. This work incorporates Kenny Niehage's contribution from [#4290](https://github.com/raullenchai/Rapid-MLX/pull/4290), adopted in [#4387](https://github.com/raullenchai/Rapid-MLX/pull/4387).

## Desktop and operational reliability

- First-run model downloads can resume after interruption and surface recoverable readiness states. ([#4342](https://github.com/raullenchai/Rapid-MLX/pull/4342))
- Drag-and-drop retry preserves destination acknowledgement, experimental pages add Simplified Chinese localization, and app shutdown or re-onboarding terminates and reaps catalog probes. ([#4321](https://github.com/raullenchai/Rapid-MLX/pull/4321), [#4313](https://github.com/raullenchai/Rapid-MLX/pull/4313), [#4298](https://github.com/raullenchai/Rapid-MLX/pull/4298))
- Recommendation cards keep model tier, footprint, capability, and caveat guidance while removing unsupported legacy speed projections. ([#4302](https://github.com/raullenchai/Rapid-MLX/pull/4302))
- Pinned snapshots already present in the shared cache can load offline, and the signed Mac package now signs and verifies every bundled Mach-O executable before notarization. ([#4332](https://github.com/raullenchai/Rapid-MLX/pull/4332), [#4346](https://github.com/raullenchai/Rapid-MLX/pull/4346))
- Support-request consent failures identify their failure class. ([#4293](https://github.com/raullenchai/Rapid-MLX/pull/4293))

## Developer and release safeguards

- Qwen4 conversion validates the pinned source and converter before staging, and release sampling excludes an explicitly non-agentic alias without changing deterministic engine, parser, or replay coverage. ([#4294](https://github.com/raullenchai/Rapid-MLX/pull/4294), [#4295](https://github.com/raullenchai/Rapid-MLX/pull/4295))
- Candidate lineage, source preflight, cancellation, release signing inventory, characterization coverage, telemetry schema coverage, and mirror inventory received fail-closed repairs. These changes improve delivery safety and do not add product behavior.
