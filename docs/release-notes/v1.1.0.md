Rapid-MLX 1.1.0 adds native Inkling 2 Mini support and turns `rapid-mlx serve` into a supervised service. A small parent process now keeps the model runner alive and exposes status, an API call log and a jobs view. Background requests can yield to interactive ones, and chat completions can continue a partial assistant message.

**Download:** [Rapid-MLX Desktop for macOS](https://github.com/raullenchai/Rapid-MLX/releases/download/rapid-mac-v1.1.0/rapid-mlx-desktop.dmg) | CLI: `rapid-mlx upgrade`

## Inkling 2 Mini

- `rapid-mlx serve inkling-2-mini-4bit` serves Inkling 2 Mini natively (26.4B MoE, about 3.4B active, Apache-2.0). Rapid-MLX uses its own bundled implementation of the looped architecture and NVFP4/MXFP8 expert weights, so no checkpoint code runs. This release covers text only ([#5907](https://github.com/raullenchai/Rapid-MLX/pull/5907)).
- Reasoning is returned separately from the answer, and tool calls come back as OpenAI `tool_calls`, both streaming and non-streaming ([#5908](https://github.com/raullenchai/Rapid-MLX/pull/5908)).

## A Supervised Server

- `rapid-mlx serve` now runs a small parent process that supervises the model runner. If the runner crashes, the parent restarts it on the same port. Stopping the parent with Ctrl-C or a signal also stops the runner and frees the port. `GET /rapid/v1/status` and `rapid-mlx status` report the runner's state, model, uptime and restart count ([#5897](https://github.com/raullenchai/Rapid-MLX/pull/5897)).
- `rapid-mlx log` and `/rapid/v1/log` show the last 1,000 API calls, kept in memory: time, method, path, status, duration and client. Request bodies, query strings and other headers are never recorded ([#5900](https://github.com/raullenchai/Rapid-MLX/pull/5900)).
- `rapid-mlx jobs` and `/rapid/v1/jobs` list agent runs in one view. `rapid-mlx jobs cancel <id>` cancels one ([#5906](https://github.com/raullenchai/Rapid-MLX/pull/5906)).
- Send `X-Rapid-Priority: background` on batch work and waiting interactive requests are admitted first. A background request that has waited 30 seconds is treated as interactive, so it is never starved. Running requests are not preempted ([#5901](https://github.com/raullenchai/Rapid-MLX/pull/5901)).

## API

- Chat completions accept `continue_final_message`. With it, the model continues a trailing assistant message instead of starting a new turn, which is useful for prefilling the start of an answer ([#5898](https://github.com/raullenchai/Rapid-MLX/pull/5898)).

## Telemetry

- Anonymous telemetry now sorts model download failures into a fixed set of failure types, and counts document inputs separately from image inputs. Only these fixed category values are added; no free text is collected. The Desktop privacy notice is updated ([#5903](https://github.com/raullenchai/Rapid-MLX/pull/5903)).
