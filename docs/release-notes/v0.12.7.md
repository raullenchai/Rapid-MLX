# v0.12.7

From this release the engine and the Rapid-MLX Desktop app carry **one** version
number, enforced in CI. 0.12.6 is skipped deliberately — see below.

## Highlights

**One version, enforced.** The two numbers were maintained by hand in different
files — `pyproject.toml` for the engine, `apps/rapid-mac/Resources/Info.plist`
for the app — with nothing comparing them, so drift was the default rather than
a risk. By 2026-08-07 the engine was 0.12.5 while the app was 0.12.6, and both
were correctly described as "the latest release": GitHub showed 0.12.6,
rapidmlx.com's install command showed 0.12.5, and neither was wrong. Asked
"which version are you running?", a user had no single answer to give.

`scripts/check_version_sync.py` now fails any PR where the two disagree, so the
chain is closed end to end: `git tag` == `Info.plist` == `pyproject.toml`.

**Why 0.12.7 and not 0.12.6.** Aligning the engine *up* to the app's 0.12.6 was
the smaller change, and it was wrong: the app 0.12.6 that users already have was
built before the work below landed. Calling this release 0.12.6 would have made
that number mean two different things — which is the exact ambiguity the change
exists to remove. Both sides move to 0.12.7 instead, and 0.12.7 genuinely
contains everything listed here.

## Privacy

- **The consent switch works.** In Settings → Privacy, pressing *Send anonymous
  usage data* wrote the preference but left the switch rendering its old value,
  so a privacy control appeared to refuse the user's choice. Measured before and
  after by driving accessibility against real builds: `0 → 0` (stuck) before,
  `0 → 1` after. (#1633)

## Models

- **Recommendations are grounded in measurement.** Every RAM tier now offers
  exactly two picks — faster and smarter — with measured ~8K peak memory and
  throughput from benchmarks run on an M2 Pro 32 GB Mac mini. Two exceptions,
  stated because they are the ones a reader would otherwise assume: the
  *smarter* primaries at 64 GB (`qwen3.6-35b-8bit`) and 96 GB+
  (`qwen3.5-122b-mxfp4`) are previously reviewed picks carried forward
  unmeasured, since both exceed the benchmark host. Their faster alternatives
  are measured. (#1640, #1629)
- **Video-generation models are no longer offered as chat models.** Eight of
  them could be selected in the picker and dead-ended *after* a download of up
  to 64 GB. (#1607)
- **A model with no compatible benchmark says "Untested"** rather than rendering
  an empty dashed track, which read as a score of zero. A missing measurement
  and a poor result must not look the same. The recommendation sweep is also
  reproducible now: persisted prefix-cache entries were inflating 8K prefill
  from ~313 to ~20,701 tok/s between reruns, so the benchmark disables the
  persisted cache. (#1643)

## Desktop app

- Model tabs consolidated into a single **Model Management** surface. (#1628)
- Low-memory quickstart recovery: a machine that fails the live memory guard is
  offered an honestly-labelled smaller model instead of a chooser whose smallest
  option is the one that just failed. (#1626)
- Syntax highlighting and markdown tables in chat. (#1620)
- The tray's *Check for updates…* reports a result instead of nothing. (#1615)
- Native accessibility semantics restored for settings toggles. (#1608)
- Brave API key link repaired. (#1631)

## Agents

- **`agents --setup` can no longer eat the operator's config.** The release gate
  runs it on machines that are also someone's daily driver; it used to back up
  and restore the real file, which failed on SIGKILL and — worse — faithfully
  restored a file that had already been damaged, so a developer's codex stayed
  pointed at a local server for weeks. `--setup` now honours `CODEX_HOME` /
  `HERMES_HOME`, the gate refuses to run against the real config directory, and
  it verifies afterwards that the real files are untouched. (#1614)

## Testing

- An AX-first GUI golden-flow suite: **six journeys plus three invariants**,
  finding controls by accessibility identifier rather than screen position, with
  committed structural snapshots so a control that vanishes, changes its
  identifier, moves in the view hierarchy or sibling order, or silently
  disables becomes a reviewable diff. The snapshots deliberately discard
  coordinates and sizes, so they say nothing about *visual* layout; a
  documented coordinate fallback remains for the first-run consent sheet, and
  menus are still driven by label. (#1613, #1616, #1621, #1619, #1606)
- Two tests that were red on `main` for reasons unrelated to any PR — a stale
  timing fixture and a measurement that sampled the whole machine's free pages —
  are fixed, so a `full_unit` failure means something again. (#1635, #1637)
