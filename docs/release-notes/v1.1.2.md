Rapid-MLX 1.1.2 is a patch release for the first run, and it adds Ternary Bonsai 2.5 27B. Model downloads recover from temporary network errors, error messages name the command or flag that fixes them, and connecting a coding agent to a server that is still loading now works.

**Download:** [Rapid-MLX Desktop for macOS](https://github.com/raullenchai/Rapid-MLX/releases/download/rapid-mac-v1.1.2/rapid-mlx-desktop.dmg) | CLI: `rapid-mlx upgrade`

## Models

- **Ternary Bonsai 2.5 27B**: new alias `bonsai2.5-27b-2bit` (8.9 GB download, text and image input). It is the successor to `bonsai2-27b-2bit`, which its publisher describes as stronger at agentic coding and multi-turn tool use at the same size, and it uses the same tool format, thinking controls and sampling defaults. Start it with `rapid-mlx serve bonsai2.5-27b-2bit`. The optional draft head published with the model is not used yet ([#5945](https://github.com/raullenchai/Rapid-MLX/pull/5945)).

## Downloads and errors

- `rapid-mlx pull`, and the automatic download in `rapid-mlx serve`, now try again after a temporary failure such as a server error, a rate limit or a dropped connection: up to three attempts, with a short wait between them. Errors that a retry cannot fix, such as a missing or gated repository, fail at once. A failed `rapid-mlx pull` ends with the exact command to run again ([#5943](https://github.com/raullenchai/Rapid-MLX/pull/5943)).
- When a model does not fit in memory, the message and the API error suggest a catalog model that is smaller than the one that failed and fits this Mac. Before, the suggestion was always the same small model ([#5943](https://github.com/raullenchai/Rapid-MLX/pull/5943)).
- Serving a local path that does not exist prints one line with the path and the two ways to fix it, and a repeated attempt on the same path prints a shorter line ([#5943](https://github.com/raullenchai/Rapid-MLX/pull/5943)).
- A prompt that is longer than the context window gets an error that says whether the limit comes from `--context-length` or `--max-prompt-tokens`, and that raising it uses more memory. The error code and HTTP status are unchanged ([#5943](https://github.com/raullenchai/Rapid-MLX/pull/5943)).
- Third-party Inkling 2 Mini builds in a weight layout that Rapid-MLX cannot load are refused before the download starts, with a pointer to `inkling-2-mini-4bit`. Before, the load failed after the full download ([#5940](https://github.com/raullenchai/Rapid-MLX/pull/5940)).

## Coding agents

- `rapid-mlx agents <agent> --setup` no longer treats a server that is still loading its model as ready. It waits for the model and shows the loading progress while it waits ([#5942](https://github.com/raullenchai/Rapid-MLX/pull/5942)).
- When a supported coding agent such as OpenCode or Codex is installed, `rapid-mlx serve` prints one line with the `rapid-mlx launch` command that connects it. The line appears only in an interactive terminal ([#5942](https://github.com/raullenchai/Rapid-MLX/pull/5942)).
- The installer prints the same pointer when it finds a coding agent on `PATH` ([#5943](https://github.com/raullenchai/Rapid-MLX/pull/5943)).

## Desktop

- The bundled engine is 1.1.2 and includes the new model and the download and error-message changes above. The only change to the app itself is that the new model is shown as "Bonsai 2.5 · 27B · 2-bit" ([#5948](https://github.com/raullenchai/Rapid-MLX/pull/5948)).
