Rapid-MLX 1.0.5 speeds up code edits, short chat turns and expert-model decoding, and adds native Raon-1 nano support for smaller Macs. New CLI monitoring and a Desktop menu bar resource card show server activity and resident models. Downloads resume, images persist across relaunch, and forced tool calls gain guided recovery.

**Download:** [Rapid-MLX Desktop for macOS](https://github.com/raullenchai/Rapid-MLX/releases/download/rapid-mac-v1.0.5/rapid-mlx-desktop.dmg) | CLI: `rapid-mlx upgrade`

## Faster Code Edits and Short Chat Turns

- Qwen3.8-27B 4-bit with MTP verifies longer prompt copies for code-editing requests on M5 Max with 36 GB. Other chips and models keep the existing copy limit ([#5852](https://github.com/raullenchai/Rapid-MLX/pull/5852)).
- Gemma 4 26B-A4B gains fused expert decoding on eligible single-stream requests. Load-time checks preserve a fallback ([#5873](https://github.com/raullenchai/Rapid-MLX/pull/5873)).

| Workload | Hardware | Decode gain |
|---|---|---:|
| Qwen3.8-27B 4-bit, MTP code edits | M5 Max, 36 GB | +45% |
| Gemma 4 26B-A4B | M5 Max | +8.3% |

- Short Qwen3.8-27B 4-bit chat turns on M5 Max with 36 GB avoid an unnecessary prefill split and admission wait. This applies to the measured single-request MTP configuration; admission-setting resolution also stays out of active decoding ([#5862](https://github.com/raullenchai/Rapid-MLX/pull/5862), [#5864](https://github.com/raullenchai/Rapid-MLX/pull/5864)).
- LFM2 MoE fused experts are enabled only on M5-generation GPUs, with a checked fallback. Other generations and unknown hardware keep the existing path; M2 Pro and M4 Pro measurements showed regressions ([#5874](https://github.com/raullenchai/Rapid-MLX/pull/5874), [#5888](https://github.com/raullenchai/Rapid-MLX/pull/5888)).

## Raon-1 Nano for Smaller Macs

- `rapid-mlx serve raon-1-nano` serves the new tool-calling model natively, using the bundled implementation without executing checkpoint code. Its official 4-bit release fits 8–16 GB Macs, with dedicated reasoning and tool-call parsing ([#5861](https://github.com/raullenchai/Rapid-MLX/pull/5861)).
- Streamed Raon tool arguments preserve literal `</parameter>` and `</function>` text inside values, so code containing those strings no longer gets truncated or becomes invalid JSON ([#5876](https://github.com/raullenchai/Rapid-MLX/pull/5876)).
- Readiness checks recognize the bundled runtime without requiring model-code consent. Checkpoints that execute external code still require consent ([#5877](https://github.com/raullenchai/Rapid-MLX/pull/5877)).

## Reliable Downloads and Model Starts

- Interrupted model downloads retain partial data and offer **Resume download**. Switching download sources reuses verified partial data, and temporary upstream failures receive bounded retries ([#5841](https://github.com/raullenchai/Rapid-MLX/pull/5841)).
- FLUX 3 Klein downloads and disk-space checks now use only the component files the runtime loads. Unused checkpoint variants no longer inflate the required space or download ([#5853](https://github.com/raullenchai/Rapid-MLX/pull/5853)).
- A fully cached pinned speculative drafter loads offline even when cache revision references are missing. Incomplete snapshots fail with an actionable message ([#5849](https://github.com/raullenchai/Rapid-MLX/pull/5849)).
- Failed server starts record a classified reason, and messages that lacked a next step now provide one. Disabling speculative decoding also sizes the context cap from actual cache requirements and rejects over-cap text prompts before prefill ([#5854](https://github.com/raullenchai/Rapid-MLX/pull/5854), [#5859](https://github.com/raullenchai/Rapid-MLX/pull/5859)).
- MTP sampling uses the same filtering distribution as plain serving, including seeded requests. LFM2 checkpoints with optional layer-layout fields left unset no longer fail request admission ([#5871](https://github.com/raullenchai/Rapid-MLX/pull/5871), [#5875](https://github.com/raullenchai/Rapid-MLX/pull/5875)).

## Desktop Images and First Run

- Desktop saves generated and edited images across relaunch. The gallery restores newest first, and deleting an image removes its stored file ([#5856](https://github.com/raullenchai/Rapid-MLX/pull/5856)).
- Images-view downloads show live progress. The compact sidebar consistently says **Agent**, reference-limit messages use correct grammar, and agent connections honor the configured home directory ([#5855](https://github.com/raullenchai/Rapid-MLX/pull/5855)).
- FLUX.2 Klein 4B and Z-Image Turbo are admitted on 16 GB Macs in Desktop and CLI using their catalog memory minimums. FLUX 3 Klein remains unavailable on 16 GB Macs ([#5857](https://github.com/raullenchai/Rapid-MLX/pull/5857)).
- The terminal installer offers to start a first chat after installation and skips the prompt in noninteractive sessions. Internal installer commands no longer consume the first-use telemetry disclosure or count as app opens ([#5846](https://github.com/raullenchai/Rapid-MLX/pull/5846), [#5845](https://github.com/raullenchai/Rapid-MLX/pull/5845)).

## Monitoring and Integration

- `rapid-mlx top` shows live server activity, model memory, queue depth and cache usage. `--once` or redirected output produces a single snapshot without prompt or response text ([#5891](https://github.com/raullenchai/Rapid-MLX/pull/5891)).
- Desktop's menu bar resource card shows resident models, memory use, active work and generation throughput, with guarded per-model unload and whole-pool release ([#5893](https://github.com/raullenchai/Rapid-MLX/pull/5893)).
- `rapid-mlx ps --json` exposes versioned server metadata without credentials; `ls --json` lists cached models. Trusted-host rejections return actionable HTTP 400 guidance. The **Build on Rapid-MLX** guide covers background services, model management and monitoring contracts ([#5894](https://github.com/raullenchai/Rapid-MLX/pull/5894), [#5892](https://github.com/raullenchai/Rapid-MLX/pull/5892)).

## API, Tools and Computer Use

- Non-streaming chat completions retry required multi-tool responses that contain no calls, plus schema-invalid required or pinned calls, with one guided decoding attempt. Successful retries combine usage; unavailable or unsuccessful recovery preserves the original error ([#5879](https://github.com/raullenchai/Rapid-MLX/pull/5879), [#5895](https://github.com/raullenchai/Rapid-MLX/pull/5895)).
- Embedding cards on `/v1/models` and `/v1/models/{id}` advertise known output dimensions, supported dimensions and input limits, plus pooling and normalization metadata ([#5889](https://github.com/raullenchai/Rapid-MLX/pull/5889)).
- `/v1/cache/clear` accepts `keep_recent` to release older text prefixes while retaining recent entries and protecting active or pinned state. Responses and cache statistics report released and retained state; no-body full clearing stays unchanged ([#5890](https://github.com/raullenchai/Rapid-MLX/pull/5890)).
- `/v1/responses` reuses the tool parse when building strict-schema responses. Tool parsing also removes duplicate parameter closers and preserves separate parallel streamed calls, including repeated calls to the same tool. An unquoted argument ending in a literal closer can still lose that tag; quoted values preserve it ([#5866](https://github.com/raullenchai/Rapid-MLX/pull/5866), [#5867](https://github.com/raullenchai/Rapid-MLX/pull/5867)).
- Browser extensions can be allowed through `--cors-origins` using `chrome-extension://*`, `moz-extension://*` or `safari-web-extension://*`. Each pattern allows all valid extension origins for that scheme; cross-origin access stays closed by default ([#5878](https://github.com/raullenchai/Rapid-MLX/pull/5878)).
- Computer use fills segmented web date/time fields with validated keystrokes and reads empty segments as empty. Changes to a neighboring segment are reported as unverified ([#5863](https://github.com/raullenchai/Rapid-MLX/pull/5863)).
- Qwen3-Reranker builds prompts in its trained format, fixing requests that failed with the checkpoint's chat template. Local adapters also work when their base model is served by catalog alias or cache path; different base models remain rejected ([#5843](https://github.com/raullenchai/Rapid-MLX/pull/5843), [#5842](https://github.com/raullenchai/Rapid-MLX/pull/5842)).
