DeepSeek V4.1 Flash 1017 on the GPTQ v2 checkpoint (introduced in 0.16.6) decodes up to about 1.9x faster on one stream. Desktop discovers updates while it stays open, and dependency repair commands now target the Python environment running Rapid-MLX.

## Highlights

- **DeepSeek V4.1 GPTQ v2 (introduced in 0.16.6) now decodes up to about 1.9x faster.** The default `RAPID_MLX_DSV41_DRAFT_DEPTH` is now 2 (was 4), and fused draft kernels read the vocabulary head once per round ([#5072](https://github.com/raullenchai/Rapid-MLX/pull/5072)), building on shared-weight multi-row verification ([#5041](https://github.com/raullenchai/Rapid-MLX/pull/5041)), lower draft overhead ([#5059](https://github.com/raullenchai/Rapid-MLX/pull/5059)) and mixed-bit fused MoE ([#5048](https://github.com/raullenchai/Rapid-MLX/pull/5048)). In a same-machine comparison (M3 Ultra 256 GB, server single stream, default settings, greedy, ~0.7–1k-token prompts), decode rose from 17.6–33.9 tok/s on 0.16.6 to 32.6–44.9 tok/s on 0.16.7 across long-prose, QA, summarize, code and structured prompts. See the [measured defaults](https://github.com/raullenchai/Rapid-MLX/blob/main/docs/engineering/performance/2026-10-21-dsv41-draft-depth.md#measured-defaults) for detailed 0.16.7 depth measurements. Depth 4 remains faster for code (49.0 tok/s) and structured output (46.5 tok/s); set `RAPID_MLX_DSV41_DRAFT_DEPTH=4` or `auto` for code-heavy workloads. Draft cost per round fell from 19.6 ms to 10.1 ms; the target model still verifies every emitted token.
- Top-1 agreement with the source model is 85.1% on held-out data and 83.2% on WikiText-2; the checkpoint introduced in 0.16.6 ([#5036](https://github.com/raullenchai/Rapid-MLX/pull/5036)) is unchanged when updating from 0.16.6. Support remains experimental, text-only and greedy-only, with tool calling unqualified; a 256 GB Mac is required (224 GB enforced minimum).

## DeepSeek V4.1

- **Faster verification**: multi-row speculative verification reads the vocabulary head once for all rows, preserving each row's exact result. Single-row decode keeps its existing path. See the [measurement tables](https://github.com/raullenchai/Rapid-MLX/blob/main/docs/engineering/performance/2026-10-20-deepseek-v41-head-gemv.md#shared-weight-read-for-multi-row-calls-2026-10-21) for timings and checkpoint details. ([#5041](https://github.com/raullenchai/Rapid-MLX/pull/5041))
- **Less draft overhead and configurable depth**: drafting skips unused confidence work and unconsumed predictions, keeps proposals on device until verification, and caches rotary position tables. `RAPID_MLX_DSV41_DRAFT_DEPTH` accepts `0` through `4` or `auto`; auto learns acceptance and round costs and falls back to target-only when drafting does not pay. Greedy output is unchanged. Auto mode can still cost more on short requests or exploratory probes. ([#5059](https://github.com/raullenchai/Rapid-MLX/pull/5059))
- **Fused MoE for mixed bit widths**: routed and shared experts with different bit widths now qualify for fused decode, including all 40 MoE layers of the v2 checkpoint on the measured M3 Ultra. Unsupported or unqualified layers retain the stock fallback. The [performance tables](https://github.com/raullenchai/Rapid-MLX/blob/main/docs/engineering/performance/2026-10-19-deepseek-v41-batched-decode.md) include target-only, concurrent, and draft-enabled results with their workloads and reproduction details; gains vary by workload and mode. ([#5048](https://github.com/raullenchai/Rapid-MLX/pull/5048))

## Desktop

- **Updates appear without a restart**: Desktop refreshes update discovery every six hours, when returning to the app with stale results, and after failures with bounded retries. Explicit update checks also refresh availability. The update offer is a compact strip that no longer reserves a large blank band, and update opt-outs remain respected. ([#5062](https://github.com/raullenchai/Rapid-MLX/pull/5062))
