## Agent chats with tools and approvals

`rapid-mlx chat --harness` offers persistent agent chats with tools and approvals; image attachments and measured model-loading progress are supported. Desktop offers harness chats behind an experimental toggle, off by default, with image attachments. ([#5309](https://github.com/raullenchai/Rapid-MLX/pull/5309), [#5317](https://github.com/raullenchai/Rapid-MLX/pull/5317), [#5310](https://github.com/raullenchai/Rapid-MLX/pull/5310), [#5311](https://github.com/raullenchai/Rapid-MLX/pull/5311), [#5324](https://github.com/raullenchai/Rapid-MLX/pull/5324))

Terminal commands inherit a restricted environment, and network clients require approval. The network policy is heuristic; terminal commands are not sandboxed. ([#5322](https://github.com/raullenchai/Rapid-MLX/pull/5322), [#5323](https://github.com/raullenchai/Rapid-MLX/pull/5323))

## New models for text, photos and video

LFM3 and LFM3-VL are available directly in Desktop. The new model aliases cover text, image understanding and video with synchronized audio. ([#5331](https://github.com/raullenchai/Rapid-MLX/pull/5331), [#5333](https://github.com/raullenchai/Rapid-MLX/pull/5333), [#5328](https://github.com/raullenchai/Rapid-MLX/pull/5328), [#5334](https://github.com/raullenchai/Rapid-MLX/pull/5334), [#5345](https://github.com/raullenchai/Rapid-MLX/pull/5345), [#5341](https://github.com/raullenchai/Rapid-MLX/pull/5341))

| Model | What it does | Requirements and defaults |
| --- | --- | --- |
| LFM3 1.7B | Native text generation | Pinned 8-bit alias |
| LFM3-VL 2B | Native image understanding | Pinned 8-bit alias |
| Ornith 1.5 122B-A10B | Text generation | Pinned 4-bit alias |
| MiniMax-H3 | Video with synchronized audio from text or a first image | `rapid-mlx serve minimax-h3`; 160 GB+ unified memory, BF16 weights; 8-step Turbo LoRA by default |

### LFM3 performance

These endpoint measurements used an M5 Max with 36 GB unified memory, macOS 27.0.1, MLX 0.32.4, Python 3.12.13 and source revision `46ac39d53`. Results are medians of five after warm-up, greedy, thinking off, with a maximum of 256 output tokens. TTFT is request start to first streamed content; decode is measured from first content to stream end. The prefill column is an endpoint proxy (prompt tokens / TTFT), including client, scheduling, first-token generation and transport overhead; it is not isolated engine prefill throughput. Results are workload-specific.

| Target prompt | Actual prompt tokens | TTFT (ms) | Prefill proxy (tokens/s) | Decode (tokens/s) |
| --- | ---: | ---: | ---: | ---: |
| 128 | 119 | 100.7 | 1,181.8 | 186.7 |
| 1K | 1,015 | 149.3 | 6,799.4 | 184.9 |
| 4K | 4,087 | 390.4 | 10,468.3 | 181.5 |
| 16K | 16,374–16,375 | 1,511.7 | 10,831.8 | 168.5 |

| Concurrent requests | Aggregate output throughput (tokens/s) |
| ---: | ---: |
| 1 | 178.6 |
| 2 | 342.8 |
| 4 | 632.6 |
| 8 | 951.5 |

Concurrency is total completion tokens divided by batch wall time, including prefill and client overhead; each request generated 256 tokens. At roughly 4K tokens, median TTFT was 390 ms with distinct cold prefixes and 113 ms on repeated identical requests. Peak reported Metal memory was 6.81 GB for text. For LFM3-VL, a repeated 1024 × 844 image and text produced 360 ms TTFT and 176 tokens/s decode, median of five; each answer was 35 tokens, so decode is a short-answer estimate. Peak reported Metal memory was 3.24 GB for vision. The machine was shared with background activity; these are not universal model limits.

## Simpler Share Compute setup

Desktop's experimental Share Compute uses a three-step checklist: add your QuickSilver key, pick or download a model, then start sharing. Credits shows requests served and credits earned this month using the same provider key. ([#5349](https://github.com/raullenchai/Rapid-MLX/pull/5349), [#5357](https://github.com/raullenchai/Rapid-MLX/pull/5357))

## New Features and Improvements

- **Desktop:** chat messages accept up to 8 images; small models are reminded of their tools in long chats; the Connect an agent page is more compact and fits narrow windows; the tool connection card no longer appears inside chats; and an optional setting releases idle models from memory. ([#5350](https://github.com/raullenchai/Rapid-MLX/pull/5350), [#5352](https://github.com/raullenchai/Rapid-MLX/pull/5352), [#5348](https://github.com/raullenchai/Rapid-MLX/pull/5348), [#5351](https://github.com/raullenchai/Rapid-MLX/pull/5351), [#5346](https://github.com/raullenchai/Rapid-MLX/pull/5346), [#5356](https://github.com/raullenchai/Rapid-MLX/pull/5356))
- **Tool calling:** DeepSeek-V4-Flash renders tool schemas and tool history natively and parses DSML tool calls, including parallel calls. ([#5344](https://github.com/raullenchai/Rapid-MLX/pull/5344), [#5347](https://github.com/raullenchai/Rapid-MLX/pull/5347))
- **Documentation:** the installer explains Intel Macs and Rosetta shells in plain words. New docs cover decode speed by Apple chip and keeping long agent tasks within the context window. ([#5354](https://github.com/raullenchai/Rapid-MLX/pull/5354), [#5355](https://github.com/raullenchai/Rapid-MLX/pull/5355))
- **Compute Share:** Qwen3.8-27B TensorFold sharing now accepts tool calls. ([#5353](https://github.com/raullenchai/Rapid-MLX/pull/5353))
- **Validation:** the stress benchmark verifies pinned snapshots before baseline comparison. ([#5302](https://github.com/raullenchai/Rapid-MLX/pull/5302))

## Bug Fixes

- Desktop's bundled file worker can import the runtime, and Desktop accepts the current chat owner schema. ([#5335](https://github.com/raullenchai/Rapid-MLX/pull/5335), [#5330](https://github.com/raullenchai/Rapid-MLX/pull/5330))
- Public Compute Share connections forward only allowed inference routes, health and model discovery; local control routes are no longer exposed. Cancelling a provider-key prompt exits cleanly. ([#5329](https://github.com/raullenchai/Rapid-MLX/pull/5329), [#5337](https://github.com/raullenchai/Rapid-MLX/pull/5337))
- Image parts count as images when checking whether a multimodal prompt fits the context window. ([#5347](https://github.com/raullenchai/Rapid-MLX/pull/5347))
- Prompt-derived output ownership keeps Flint and LFM2.5 reasoning separate from content and tool calls. Request-local ownership also handles Qwen tool envelopes, and unfinished reasoning at a length stop remains in the reasoning field rather than being copied into content. ([#5308](https://github.com/raullenchai/Rapid-MLX/pull/5308), [#5318](https://github.com/raullenchai/Rapid-MLX/pull/5318), [#5325](https://github.com/raullenchai/Rapid-MLX/pull/5325))
- Jina v3.5 reranking loads separate projector weights and documents the 0–1 relevance score mapping from cosine. Complete resharded text checkpoints can load even if their index describes an older shard layout. ([#5316](https://github.com/raullenchai/Rapid-MLX/pull/5316), [#5315](https://github.com/raullenchai/Rapid-MLX/pull/5315))
- Packaged digests now cover the three mirrored 0.16.10 aliases. Test compatibility fixes cover pytest 9.2 and Python 3.10 harness collection. ([#5307](https://github.com/raullenchai/Rapid-MLX/pull/5307), [#5327](https://github.com/raullenchai/Rapid-MLX/pull/5327), [#5314](https://github.com/raullenchai/Rapid-MLX/pull/5314))
