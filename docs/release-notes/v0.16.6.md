Rapid-MLX 0.16.6 makes `qwen-image` serve Qwen-Image-2.1, adds an eight-step Qwen-Image-2.1-Turbo alias, and fixes concurrent image requests. DeepSeek V4.1 Flash 1017 moves to new GPTQ default weights that track the source model more closely, decodes about 1.5x faster on one stream, and can batch concurrent requests when you opt in. Coding-agent launches now keep their connection across restarts and authenticate cleanly, and a chat model you already downloaded starts with zero downloads.

## Upgrade note

- **One-time image re-download**: the upstream `flux-schnell` and `qwen-image` repositories were re-created, so the old pinned revisions no longer download. `flux-schnell` is re-pinned to the new build, so a cached copy downloads once more on first use. `qwen-image` now resolves to the same checkpoint as `qwen-image-2.1`; if you already have `qwen-image-2.1` cached, nothing is downloaded, and otherwise the first pull downloads it. ([#4993](https://github.com/raullenchai/Rapid-MLX/pull/4993), [#5000](https://github.com/raullenchai/Rapid-MLX/pull/5000))

## Images

- **`qwen-image` serves Qwen-Image-2.1**: the bare `qwen-image` name now serves the latest Qwen image model, Qwen-Image-2.1 (4-bit, 8 GB minimum memory, generate and edit, 40 default steps). This also fixes cold `rapid-mlx pull qwen-image` and `rapid-mlx pull flux-schnell`, and the same downloads in the Desktop app, which failed with a revision-not-found error. ([#5000](https://github.com/raullenchai/Rapid-MLX/pull/5000), [#4993](https://github.com/raullenchai/Rapid-MLX/pull/4993))
- **Qwen-Image-2.1-Turbo**: new `qwen-image-2.1-turbo` alias for the official distilled checkpoint. It renders a 1024x1024 image in about 22 s on an M5 Max with an about 28 GB peak, so it fits a 36 GB Mac. It runs only its published eight-step schedule without guidance; other `steps` or `guidance` values return HTTP 400. Text-to-image only. ([#5003](https://github.com/raullenchai/Rapid-MLX/pull/5003))
- **Concurrent image requests no longer fail**: an image request that arrived while another render was running could fail with HTTP 500 (`There is no Stream(cpu, 2) in current thread`). All image work now runs on one dedicated worker thread. ([#5005](https://github.com/raullenchai/Rapid-MLX/pull/5005))

## DeepSeek V4.1

- **New default weights for DeepSeek V4.1 Flash 1017**: the alias now serves a GPTQ build that is closer to the source model (mean KL 35–44% lower, top-1 agreement 3.5–5.9 points higher than the previous build). Existing users re-download once (338.8 GB). Decode is about 5–12% slower than with the previous build; a 256 GB Mac is still required. The previous build remains available as revision `v1` of the model repository. ([#5036](https://github.com/raullenchai/Rapid-MLX/pull/5036))
- **About 1.5x faster single-stream decode**: fused decode kernels and an exact head and router GEMV take single-stream decode at 1K context from 11.6 to 16.6–16.9 tok/s on M3 Ultra (10.4 to 17.5 tok/s at 16K), measured with the previous weights build. Greedy output is identical to 0.16.5. ([#5024](https://github.com/raullenchai/Rapid-MLX/pull/5024), [#4986](https://github.com/raullenchai/Rapid-MLX/pull/4986))
- **Correct output after a rejected speculative verify**: once the context was longer than the sliding window, a rejected draft could overwrite window entries that later tokens still attended to, and greedy speculative output could drift from plain greedy decoding. Those entries are now restored. ([#4987](https://github.com/raullenchai/Rapid-MLX/pull/4987))
- **Lower memory while loading**: DeepSeek V4.1 native loads now release each shard's file cache after materializing it, removing a load-time memory spike (compressor peak 26 GB → under 1 GB on a 256 GB M3 Ultra) that could get the server killed during startup. ([#5034](https://github.com/raullenchai/Rapid-MLX/pull/5034))
- **Opt-in batched decode for concurrent requests**: set `RAPID_MLX_DSV41_LANES` to `2`, `4` or `8` so that many requests share decode steps instead of queueing. Batched mode turns drafting off; unset or `1` keeps the serial path. ([#4982](https://github.com/raullenchai/Rapid-MLX/pull/4982))
- **Kernel troubleshooting switch**: `RAPID_MLX_DSV41_FUSED=0` runs every V4.1 custom kernel on its stock path, with the same output and slower decode, in case a kernel fails on an unqualified chip or macOS version. ([#5029](https://github.com/raullenchai/Rapid-MLX/pull/5029))

## Coding agents

- **Connections survive restarts**: `rapid-mlx launch <agent>` keeps a private loopback key and port across restarts, starts a stopped local server, waits for the saved model and opens the agent. The same command works the next day, and Desktop shows it beside each supported agent. ([#4979](https://github.com/raullenchai/Rapid-MLX/pull/4979))
- **Claude Desktop setup**: `rapid-mlx launch claude-desktop` sets up a connection through Claude Desktop's in-app Gateway configuration. Local models appear in its model picker as `claude-opus-rapid-mlx`, `claude-sonnet-rapid-mlx` and `claude-haiku-rapid-mlx`, with a memory-fit, tool-capable default per tier. `--remove` turns the mapping off. ([#4981](https://github.com/raullenchai/Rapid-MLX/pull/4981))
- **Claude Code authenticates to the local server**: `rapid-mlx launch claude-code` no longer fails with `401 Invalid API key` on a machine with a saved subscription login, and the server accepts `x-api-key` on every authenticated route. ([#4998](https://github.com/raullenchai/Rapid-MLX/pull/4998))
- **Codex and OpenCode launch fixes**: Codex launches pin the selected local model and show the served context window ([#5016](https://github.com/raullenchai/Rapid-MLX/pull/5016)). OpenCode 2.x launches no longer stop with a command-line argument error, use the selected local model over project settings, run with their own private server, and no longer exit before the first request ([#4995](https://github.com/raullenchai/Rapid-MLX/pull/4995), [#5023](https://github.com/raullenchai/Rapid-MLX/pull/5023), [#5026](https://github.com/raullenchai/Rapid-MLX/pull/5026)). Commands that OpenCode runs keep your real HOME, so `git commit` keeps your identity, `gh` keeps its login, and HOME-based toolchains work as usual ([#5030](https://github.com/raullenchai/Rapid-MLX/pull/5030)).
- **Missing agent CLI caught before any download**: `rapid-mlx launch <agent> --run` checks that the agent's CLI is installed (using the same login-shell PATH the launch uses) before choosing, downloading or starting a model, and prints the install command if it isn't. ([#5028](https://github.com/raullenchai/Rapid-MLX/pull/5028))
- **More reliable launches**: a second agent reuses a compatible model the local server is already serving ([#4996](https://github.com/raullenchai/Rapid-MLX/pull/4996)). Isolated launches ignore existing cloud settings and project overrides that would point them away from the local server ([#5001](https://github.com/raullenchai/Rapid-MLX/pull/5001)). Hermes gets the served context limit instead of a fixed 32K ([#4997](https://github.com/raullenchai/Rapid-MLX/pull/4997)). Agent configs are written only after the server is serving the selected model ([#4978](https://github.com/raullenchai/Rapid-MLX/pull/4978)).
- **From first reply to an agent**: after a first successful local request, the server, `rapid-mlx chat` and Desktop show the base URL, model ID and agent setup commands. ([#4970](https://github.com/raullenchai/Rapid-MLX/pull/4970))

## CLI and models

- **Zero-download start for a cached chat model**: `rapid-mlx serve`, `rapid-mlx chat` and the bare command prefer a complete local chat model that fits memory before downloading anything. Models in another MLX app's default model folder are found and served in place; uncataloged models carry a "not catalog-tested" note. ([#4971](https://github.com/raullenchai/Rapid-MLX/pull/4971))
- **`pull` and `rm` ignore external model folders**: `rapid-mlx pull <alias>` (and the Desktop download) no longer crashes, and `rapid-mlx rm <alias>` no longer fails, when the model also exists in an external folder. ([#5031](https://github.com/raullenchai/Rapid-MLX/pull/5031))
- **Actionable startup and download failures**: a local model that cannot start now reports the cause, such as missing config, weights or shards, a truncated file, or a Metal failure, together with a retry command ([#4965](https://github.com/raullenchai/Rapid-MLX/pull/4965)). Failed pulls name the cause (disk space, network, gated access) and give a retry command ([#4978](https://github.com/raullenchai/Rapid-MLX/pull/4978)).
- **DFlash drafters from the shared blob store**: drafters downloaded into a model cache that deduplicates files across repositories no longer fail with `safetensors index entry escapes the checkpoint directory`. ([#5017](https://github.com/raullenchai/Rapid-MLX/pull/5017))
- **Experimental TensorFold aliases**: these experimental lanes are available, each with its own minimum memory: `qwen3.8-27b-tensorfold` (48 GB), `nemotron-3.5-lightning-tensorfold` (48 GB), `gemma-4-26b-tensorfold` (48 GB), `bonsai2-27b-tensorfold` (96 GB), `qwen3.8-flash-next-tensorfold` (192 GB) and `deepseek-v4-flash-tensorfold` (256 GB).

## Compute sharing

- **Qwen3.8-27B on 32–47 GB Macs**: `rapid-mlx share qwen3.8-27b --quicksilver` now serves the MTP 4-bit lane (`qwen3.8-27b-4bit`) below the 48 GB TensorFold floor instead of failing. Below 32 GB, the existing memory-floor refusal still applies. ([#5022](https://github.com/raullenchai/Rapid-MLX/pull/5022), [#5027](https://github.com/raullenchai/Rapid-MLX/pull/5027))
