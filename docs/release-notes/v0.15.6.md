Rapid-MLX 0.15.6 makes the first local-model session easier to start and long-running servers more predictable. It adds an interactive command-line front door, keeps prompt compression explicit, and strengthens model setup, cache reuse, memory recovery, and bring-your-own-model diagnostics.

## Highlights

**A clearer first step** — Running bare `rapid-mlx` in a terminal now opens a compact interactive front door. It shows the active or last-used model when available, distinguishes the quick-start choice from the best model for the current Mac, and waits for an explicit keypress before chatting, starting a server, connecting a detected coding agent, or opening the model picker. `rapid-mlx --help` is grouped by task, while non-interactive use keeps deterministic copy-and-paste guidance. ([#4120](https://github.com/raullenchai/Rapid-MLX/pull/4120))

**Lossless prompts by default** — PFlash prompt compression is off for every alias unless you explicitly select `--pflash auto` or `--pflash always`. Existing opt-in acceleration remains available. When an opted-in request is compressed, supported APIs report the original and retained token counts through response metadata or a response header, so compression is visible. ([#4104](https://github.com/raullenchai/Rapid-MLX/pull/4104))

**Agent setup ready for the first task** — Generated configurations preserve explicit user settings, use live server model and context metadata, and handle authenticated local servers without storing secrets in generated files. Codex, OpenCode, Claude, and Pi setup paths now produce usable first-run configurations while keeping user choices authoritative. ([#4093](https://github.com/raullenchai/Rapid-MLX/pull/4093), [#4101](https://github.com/raullenchai/Rapid-MLX/pull/4101))

**More reliable bring-your-own-model flows** — External revision probes are bounded and respect warm-cache and offline behavior, and requested server log levels take effect before model-serving modules are imported. When telemetry is enabled, BYOM preflight, suggestion, support-request, and import outcomes use closed categories; local paths and custom model names are not transmitted. ([#4091](https://github.com/raullenchai/Rapid-MLX/pull/4091), [#4095](https://github.com/raullenchai/Rapid-MLX/pull/4095), [#4107](https://github.com/raullenchai/Rapid-MLX/pull/4107))

**Safer memory and shared-cache reuse** — Completed single-request KV state is released promptly, and an idle server remeasures reclaimed memory before rejecting new work at the Metal memory limit. Model loading now accepts valid deduplicated shared Hugging Face blob layouts while retaining containment, size, and digest checks. A stray non-model directory named like a catalog alias no longer hides that alias. ([#4111](https://github.com/raullenchai/Rapid-MLX/pull/4111), [#4103](https://github.com/raullenchai/Rapid-MLX/pull/4103))

**Clef decision models in System One** — The System One service can run Clef and Clef-Flash models for text decisions, ranking, bounded images, and multi-frame video. Unsupported media and oversized requests fail with explicit errors, and the optional runtime remains isolated from the base install. ([#4061](https://github.com/raullenchai/Rapid-MLX/pull/4061))

## More improvements

- Supported MTP models yield fairly at token boundaries and use ordinary batching when requests overlap, while a single request retains the qualified speculative path. ([#4072](https://github.com/raullenchai/Rapid-MLX/pull/4072), [#4074](https://github.com/raullenchai/Rapid-MLX/pull/4074))
- Community Qwen3.8 checkpoints automatically receive the correct reasoning and nested tool-call parsers without weakening checkpoint safety policy. ([#4099](https://github.com/raullenchai/Rapid-MLX/pull/4099))
- Failed video jobs remove partial artifacts before publishing their terminal failure state. ([#4025](https://github.com/raullenchai/Rapid-MLX/pull/4025))
