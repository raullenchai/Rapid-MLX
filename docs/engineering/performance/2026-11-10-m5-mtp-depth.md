# M5 Max MTP depth qualification

The 35B MoE target's implicit MTP maximum changes from 1 to 4 only for GPU
generation 17 / Max / exactly 36 GiB, MLX 0.32.3 and macOS 27.0.1, with an
installed MTP head, single-request MTP mode, family `qwen3_5_moe_text`, geometry
`(2048, 512, 256, 8, 4, 64)` and affine expert quantization. Other contexts retain
their configured depth, normally 1. Explicit JSON and environment priority are
unchanged. The existing request-local controller chooses depths below the cap;
this does not force four drafts each round.

The loaded argument dataclass omits quantization. Qualification therefore reads
uniform instantiated expert projections, including fused gate/up projections;
unweighted activation modules are excluded.
8-bit router projections do not describe the expert format. Missing, mixed or
unsupported expert formats cannot qualify the row. GPU cores are unavailable
from this MLX device-info API; the entry pins generation, tier and exact memory
without inventing a core count. Unknown memory does not borrow this entry.

## Performance

Measured policy commit `1cc45b63c4d1ed6ec2023eb90ecd765b15f2b326`, main baseline
`bb6ea903645d65b14c231cd90e26d3b04cc55569`, 2026-11-10. Three interleaved fresh
servers per arm, middle order reversed, sustained idle admission, one GPU server
at a time under the verified GPU lock. Cached weights, excluded short warmup,
564 templated prompt tokens and 256 greedy output IDs, thinking disabled.
Client decode timing excludes the first chunk and TTFT. All valid reps retained.

Cap 4 gains 4.80% over main MTP and 6.19% over plain, with non-overlapping

166.09/140.88 tok/s, despite 2.383/2.406 tokens per forward. The controller is
retained. These M5 results do not qualify another GPU generation or tier.
