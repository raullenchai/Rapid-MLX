## Method and restart contract

`scripts/deepseek_v41_gptq.py` provides `inventory`, `shards`, `default-config`,
`estimate`, `init`, `run`, `select-recipe`, `assemble`, `reference`, `drift`, and
`milestone`. Held-out tracking is in `deepseek_v41_gptq_quality.py`. The numerical kernel
is in `deepseek_v41_gptq_quant.py` (MIT notice retained); bounded source reads,
native shard writes and typed state serialization are in `deepseek_v41_gptq_io.py`.
No checkpoint Python executes and no command downloads model data.

The default recipe uses affine group 64, column order, lazy blocks of 128,
float32 CPU Cholesky of the damped inverse, and group grids refitted on updated
weights. Integer codes are packed directly into native U32 words; three-bit
codes span word boundaries. BF16 scale/bias grids are used during rounding.
Routed gate/up use two bits and down uses three. Attention `wq_a/wq_b/wkv/wo_b`
and shared `w1/w3/w2` use four bits. Grouped `wo_a`, routers, indexer, compressor,
Engram projections, norms, HC, embedding and head retain the existing build's
policy. DSpark retains its existing native sidecar layout and four-bit RTN
experts. Engram uses six-bit/group-32 affine rows and the existing SSD reader;
the synthetic build verifies that this width loads and runs, so no eight-bit
fallback is necessary on the tested runtime.

Every layer observes attention inputs using original attention projections,
quantizes those projections, and replays attention before collecting FFN inputs
and **true** routing. Each expert gets `sum(g * x x^T)`, using the actual selected
router weight including its scaling factor. Gate/up share an inverse factor.
Down inputs come from that expert's quantized gate/up, native clamps and SwiGLU.
The routed down input remains float32; shared down input uses the native BF16
cast. Dense Hessians include every calibration token. Processing one expert at
a time bounds the expert-Hessian working set; repeated mmap passes trade I/O
for memory. Projection reports compare weighted squared output error against
source energy, on identical inputs for RTN and GPTQ. Down comparisons condition
on quantized gate/up inputs, rather than measuring an end-to-end FFN loss.

Default damping is `0.1 * mean(diag(H))`; below 2,048 routed tokens it is `1.0 *`
the mean, both configurable. Unseen experts are explicitly recorded and retain
RTN weights: no calibration signal exists for a zero Hessian. Optional
`low_token_bump` promotes the entire affected projection bank by one bit, capped
at four. Native stacked banks have one width per projection, so a per-expert
width bump would require a runtime format change. Cumulative resident-budget
checks reject unaffordable promotions; this flag is off by default.

The pilot (`pilot: true`) also tries three-bit gate/up and measures complete
block output movement with four-bit dense projections versus source dense
projections, keeping the quantized routed experts in both branches. Its reference
branch recomputes attention and routing independently. `select-recipe` selects
the eight largest block movements, then buys whole-layer three-bit gate/up banks
in measured benefit order while the exact payload budget permits. The final
run starts from embedding again with that selected recipe, so its inputs include
all preceding quantization errors. The eight layers cannot be selected from a
two-layer smoke; a complete pilot is needed.

Windows remain independent. Each boundary stores BF16 `[1,T,4,5120]` residuals,
float32 outgoing HC pre-mixes, token/hash IDs, source KV/index cache objects and
**every chunk's** top-k indices/candidate masks. Object aliases are preserved.
Indices include a chunk-local window offset: retaining only the final chunk, or
changing `prefill_chunk` during resume, is incorrect. Native attention,
compression, hashing and HC functions perform the arithmetic.

`checkpoint.json` commits each boundary atomically. A completed attention and
FFN-input phase is also a restart point within the current layer. Final runs
release the obsolete input boundary there, and replace attention windows with
final output windows individually. A crash before a phase commit replays that
phase; a crash during final-window writes preserves already-committed windows.
The recipe, source inventory, calibration content and token hashes bind a run.
Completed layer files and reports have SHA256 completion records; assembly
rejects missing, changed or mixed-run artifacts. Native tensor writes are
range-bounded, never assembled into a full expert bank in RAM.

## Capacity and environment

Sizes below are decimal GB; resident accounting is the same `Entry.nbytes`
payload accounting as the existing allocator. Headers are reported separately.
All 384 experts are retained. The four-bit dense pilot is **208.506 GB resident**;
eight dense layers at eight bits make **209.020 GB**. At the 210 GB target there
is insufficient room for one complete extra three-bit gate/up layer (about

adds **172.037 GB of SSD payload**, outside the resident budget. A final complete

The default memory policy caps RSS and MLX active+cache **individually** at
26,000,000,000 bytes, sets MLX allocation/cache limits and polls RSS every 20 ms,
including during native operations. Crossing the cap exits with status 86;
the last committed phase survives. Unified-memory counters overlap and must not
be added. This sampled watchdog cannot prevent an instantaneous allocation
overshoot; the printed conservative estimate provides allocation headroom.
Per-layer and per-expert elapsed times and measured memory counters are logged.

## Command sequence

Use fresh parts/scratch directories for each recipe. Copy the corpus to the target and use paths relative to its manifest.
Prepare the held-out reference cache described below before `init`.
The source host exports a header inventory once; `shards` thereafter works without source shard bodies.
The staged source needs only the listed shards and tokenizer metadata, not a
complete source index/config directory. No download or source deletion is done
by the builder.

```sh
PY=.venv/bin/python
TOOL=scripts/deepseek_v41_gptq.py
ROOT=${DSV41_SCRATCH_ROOT}/gptq
HELDOUT_REF="$ROOT/heldout-reference"
mkdir -p "$ROOT" "$HELDOUT_REF"
# SOURCE is the immutable revision-pinned source directory, on its host.
"$PY" "$TOOL" inventory --source "$SOURCE" \
  --source-revision 1bae0e1088993b9b82de08f59de5be5a34e42170 \
  --output "$ROOT/source-manifest.json"
"$PY" "$TOOL" default-config > "$ROOT/pilot.json"
"$PY" "$TOOL" shards --manifest "$ROOT/source-manifest.json" --component top \
  > "$ROOT/top-shards.txt"
# Orchestrator copies these files, tokenizer.json and tokenizer metadata into STAGE.
STAGE="$ROOT/staged-source"
rsync -a "$ASSEMBLY_HOST:$STUDIO_HELDOUT_REF/reference.json" "$HELDOUT_REF/"
rsync -a "$ASSEMBLY_HOST:$STUDIO_HELDOUT_REF/boundary-0" "$HELDOUT_REF/"
"$PY" "$TOOL" estimate --source "$STAGE" --manifest "$ROOT/source-manifest.json" \
  --recipe "$ROOT/pilot.json" --slices "$CALIBRATION_MANIFEST" --tokens 16384 \
  --reference "$HELDOUT_REF"
"$PY" "$TOOL" init --source "$STAGE" --manifest "$ROOT/source-manifest.json" \
  --recipe "$ROOT/pilot.json" --slices "$CALIBRATION_MANIFEST" --tokens 16384 \
  --parts "$ROOT/pilot-parts" --scratch "$ROOT/pilot-state" \
  --reference "$HELDOUT_REF"
rsync -a "$ROOT/pilot-parts/run.json" "$ROOT/pilot-parts/source-manifest.json" \
  "$ROOT/pilot-parts/engram_token_map.json" "$ROOT/pilot-parts/heldout-reference.json" \
  "$ASSEMBLY_HOST:$COLLECTED_PARTS/"
# Top source shards can now be removed from STAGE after successful init.
for LAYER in $(seq 0 39); do
  "$PY" "$TOOL" shards --manifest "$ROOT/source-manifest.json" --component "$LAYER" \
    > "$ROOT/layer-shards.txt"
  rsync -a --files-from="$ROOT/layer-shards.txt" "$SOURCE_HOST:$SOURCE/" "$STAGE/"
  for BOUNDARY in "$LAYER" "$((LAYER + 1))"; do
    rsync -a "$ASSEMBLY_HOST:$STUDIO_HELDOUT_REF/boundary-$BOUNDARY" "$HELDOUT_REF/"
  done
  "$PY" "$TOOL" run --source "$STAGE" --manifest "$ROOT/source-manifest.json" \
    --recipe "$ROOT/pilot.json" --layer "$LAYER" \
    --parts "$ROOT/pilot-parts" --scratch "$ROOT/pilot-state"
  rsync -a "$ROOT/pilot-parts/model-layer-$LAYER.safetensors" \
    "$ROOT/pilot-parts/layer-$LAYER-"*.json "$ASSEMBLY_HOST:$COLLECTED_PARTS/"
  rsync -a "$ROOT/pilot-parts/heldout-drift.jsonl" "$ASSEMBLY_HOST:$COLLECTED_PARTS/"
  rsync -a "$ROOT/pilot-state/heldout/" "$ASSEMBLY_HOST:$QUALITY_STATE/"
  # Verify the exported payload against layer-L-complete.json before removing
  # its LOCAL copy. Retain local JSON records for budget/selection checks.
  while IFS= read -r SHARD; do rm -- "$STAGE/$SHARD"; done < "$ROOT/layer-shards.txt"
  # HELDOUT_REF is the small Mac's stage; preserve the Studio archive.
  rm -r -- "$HELDOUT_REF/boundary-$LAYER"
done
"$PY" "$TOOL" select-recipe --parts "$ROOT/pilot-parts" --output "$ROOT/final.json"
# Repeat init/copy/run/export/delete with final.json and fresh final-parts/state.
# Use the full prepared manifest for the 1.5M-token final pass if desired.
```

`shards --index` also accepts the original `model.safetensors.index.json`,
without shard bodies. Add `--total-tokens 1500000` to final `estimate`/`init`
for the 92-window run; the last window is shortened to 9,056 tokens.

If interrupted, repeat `run` with the same arguments; omitting `--layer` resumes
the committed next layer. Do not change source files, recipe, window order or
chunk sizes. Export payloads only after their completion record appears.
The local payload-removal comment above is an orchestrator responsibility;
`run` never deletes source shards or completed native payloads.

On the Studio NVMe, collect all final outputs, JSON records,
`run.json`, `source-manifest.json`, and `engram_token_map.json`. Supply the source
shards for top/DSpark/Engram conversion, then assemble and evaluate:

```sh
"$PY" "$TOOL" assemble --source "$SOURCE" --manifest "$ROOT/source-manifest.json" \
  --recipe "$ROOT/final.json" --parts "$COLLECTED_PARTS" --destination "$NEW_BUILD"
"$PY" scripts/evaluate_deepseek_v41_rd.py collect --model "$NEW_BUILD" \
  --model-revision 1bae0e1088993b9b82de08f59de5be5a34e42170 \
  --slices "$HELDOUT_MANIFEST" --tokens 512 --serving-qmv --output "$CANDIDATE_LOGITS"
"$PY" scripts/evaluate_deepseek_v41_rd.py compare \
  --reference "$REFERENCE_LOGITS" --candidate "$CANDIDATE_LOGITS" --output "$QUALITY_JSON"
```

Assembly hard-links completed layers, so parts and destination must share a
filesystem. It writes top, separate Engram weight/affine files, the DSpark
subdirectory, native config/module maps/index, byte accounting, per-layer statistics, provenance and a
`gptq-artifacts.json` inventory of names, sizes and SHA256s. Timing/memory
profiles stay outside the assembled build, allowing byte-identical model
artifacts after a restart.
Immutable product aliases/pins still identify the previously qualified build;
a new candidate needs independent hashes and qualification before any pin update.

## Held-out layer and milestone tracking

The held-out set is the existing **38 slices × 512 tokens = 19,456 tokens**,
identified by the ruler's token files and corpus hashes. It is independent of
calibration. New CLI runs require `init --reference`; matching source/reference
identities and disjoint corpus hashes/token windows are checked. Calibration
errors retain their old fields for allocator compatibility and additionally
appear under `calibration`. Every fitted projection, including three-bit pilot
alternatives, gets a separate `heldout` report. Held-out activations are used
only for forward/error measurement: no fitting Hessian, damping or rounding
decision uses them. An unseen held-out expert reports `status: unobserved` and
null errors, never a fabricated zero. Older API-only runs explicitly report
`not_configured`; the CLI does not permit new calibration-only builds.

On the Studio, generate the original state cache once, using the exact ruler
tokens. Both residual streams and typed auxiliary/cache state are mmap-readable
safetensors. The residual tensor is BF16; HC pre-mixes, shared KV/index cache
objects, compressor state, hashes and per-chunk selections retain native types.
Every boundary has a hash-verified completion record. `--through-layer` can
extend the cache a layer at a time using only that layer's source shards.

```sh
# STUDIO_HELDOUT_REF is a fresh archive directory on Studio NVMe, outside
# the protected existing-build directory. HELDOUT_REF is its small local stage.
"$PY" "$TOOL" reference --source "$SOURCE" --manifest "$ROOT/source-manifest.json" \
  --tokens-from-cache "$REFERENCE_LOGITS" --reference "$STUDIO_HELDOUT_REF"
# Alternatively: --slices "$HELDOUT_MANIFEST" --tokens 512
# Optional --write-logits writes a new reference cache in evaluator format.
# A bounded smoke uses --through-layer 1. Repeating resumes the next layer.
```

Printed storage estimates for the real ruler: **0.797 GB residual per boundary**,
**36.29 GB across all 41 complete boundary states**, **10.06 GB reference logits**
if regenerated, and approximately **0.60 GB FFN spill** per active pass. The
small Mac stages only `reference.json` and the current original boundaries
`boundary-L`/`boundary-(L+1)`; boundary 0 is needed for initialization. Keep the
full archive and assembly on the Studio NVMe. Held-out prefixes retain one
committed boundary, with an extra boundary during commit/restart. Allow roughly
**7 GB additional local space** for staged references, one candidate prefix,
attention/FFN spill and commit overlap. The shape-based allowance is **6.75 GB**;
final local disk becomes **180.27 GB / 270.92 GB** for 0.6M / 1.5M tokens.
The extra attention error probes add a **1.12 GB RAM allowance**, bringing the
planning bound to about **13.88 GB**. `estimate --reference` prints these costs.
Allow another approximately **2 GB** if tracking an accessible baseline locally,
plus its staged native layer payload. Do not copy an entire baseline
Engram table to the small Mac; evaluate that baseline on the Studio.

`run` advances the held-out quantized prefix alongside calibration, computes
local drift from original layer inputs, and appends/prints
`PARTS/heldout-drift.jsonl`. It checkpoints before releasing the prior held-out
prefix. `--quality-scratch` relocates prefix state; `run --reference` can rebind
machine-local paths to the same reference identity after copying a run.
`--rtn-build DIR` adds an accessible baseline to automatic rows. Otherwise the
baseline is evaluated after each per-layer export on the Studio:

```sh
# Copy completed native payload, all layer JSON, run/source metadata and
# heldout-reference.json into COLLECTED_PARTS on the Studio, as above.
rsync -a "$ROOT/pilot-state/heldout/" "$ASSEMBLY_HOST:$QUALITY_STATE/"
# Execute on Studio, with the same reference content and copied prefix state:
"$PY" "$TOOL" drift --source "$SOURCE" --manifest "$ROOT/source-manifest.json" \
  --reference "$STUDIO_HELDOUT_REF" --build "$COLLECTED_PARTS" --layers 0-3 \
  --baseline "$RTN_BUILD" --scratch "$QUALITY_STATE" --metrics "$ROOT/drift.jsonl"
# Compare an arbitrary block using original inputs at boundary 20:
"$PY" "$TOOL" drift --source "$SOURCE" --manifest "$ROOT/source-manifest.json" \
  --reference "$STUDIO_HELDOUT_REF" --build "$BUILD_A" --baseline "$BUILD_B" \
  --layers 20-23 --block-start 20 --scratch "$ROOT/block-state" \
  --metrics "$ROOT/block-drift.jsonl"
```

`--layers 20-23` without `--block-start` means cumulative **0..L**, replaying a
missing prefix when needed. With `--block-start 20` it means **20..L** and rows
explicitly say `cumulative_scope: block`. Local error always feeds the original
boundary L and its original shared state to the candidate layer; cumulative
error carries the candidate's own shared state. No GPTQ fitting is required.
`--update-parts-stats` backfills held-out errors into older GPTQ parts and
re-hashes completion records; complete builds, including the published RTN
baseline, are always read-only. Skip projection probes with
`--skip-projection-errors` when only residual drift is needed.

Each JSONL row contains `schema_version`, `layer`, `prefix_start`,
`cumulative_scope`, reference/candidate/baseline identities and execution
backends. `candidate` and optional `baseline` each contain `local` and
`cumulative`. Each metric object has `relative_frobenius_error = ||Q-R||F/||R||F`,
`mean_token_cosine_similarity` over flattened four-stream token vectors,
`tokens`, `slices` with the same two metrics, and the worst slice values/names
for error and cosine independently. Row append is fsynced, incomplete terminal
lines are discarded after interruption, and identical reruns are deduplicated.
The projection loss is a **squared** relative output loss; residual drift uses
the unsquared Frobenius norm. True routing weights determine expert error
aggregation. RTN projection probes use the candidate projection's bit width;
the published baseline's drift uses its actual stored tensors and widths.

Milestone KL splices candidate layers 0..L with streamed original layers L+1..39,
using unchanged original embedding/norm/head. A complete native build or a
partial GPTQ run is accepted. It writes the evaluator's tokens/logits/mass/
metadata cache, calls its unchanged `compare`/`token_metrics`, and writes
`quality.json` with `mean_domain_kl_nats`, `worst_domain_kl_nats` and per-slice
`top1_flip_rate`. No complete decoder or expert bank becomes resident.

```sh
"$PY" "$TOOL" milestone --source "$SOURCE" --manifest "$ROOT/source-manifest.json" \
  --reference "$STUDIO_HELDOUT_REF" --build "$COLLECTED_PARTS" \
  --last-quantized-layer 3 --scratch "$ROOT/milestone-state" \
  --logits-reference "$REFERENCE_LOGITS" --output "$ROOT/milestone-L3"
# -1: no candidate layers; 39: all candidate layers. Keep top/embed/head unchanged.
```

The original source tail is recomputed for each milestone; each pass retains
only its current boundary. Full ruler logits cost another 10.06 GB per
milestone. Run milestones and assembly on Studio; only per-layer GPTQ and its
small held-out forward need to run on the 36 GB Mac. The earlier M5 scheduling
ranges exclude this new held-out work and reference generation; replace them
with measured combined per-layer timings before launching a full run.

### Compact reference and KL interpretation

Reference mode `--compact-k 128` saves per-position int32 token IDs, FP32
log-probabilities for the reference top-k support, FP32 residual probability
mass, FP32 full-vocabulary logsumexp and int32 original argmax. The original
full-vocabulary argmax is saved independently, preserving tie-breaking. The
head is evaluated for the complete vocabulary in bounded chunks before
compaction. There is no model quantization or softmax truncation in this step.

For original probabilities p, build probabilities q, reference support S,
P = sum outside S of p and Q = sum outside S of q, the reported metric is

```text
KL_bucket = sum(i in S) p_i * (log p_i - log q_i) + P * log(P / Q)
KL_full - KL_bucket = P * KL(p_tail / P || q_tail / Q) >= 0
0 <= error <= P * log(Q / min(i outside S) q_i)   [finite positive q]
```

Zero-mass terms contribute zero. The tail Q is computed stably from the build's
actual excluded logits, rather than subtracting a rounded top-k sum from one.
The support contribution is exact up to FP32 storage; the tail is one bucket.
The displayed upper bound follows from conditional entropy being nonnegative;
it can be large. There is **no universal finite small-error bound**, and one
slice's validation does not guarantee 1e-3 error for a different model or ruler.
P99 is the percentile of per-position bucket KL, also a lower bound on the full
KL percentile; its error has not been qualified by the mean-error criterion.
Top-1 agreement is exact regardless of k.

`stage-other` resumes at group boundaries; orphan `.partial` files and unrecorded
final files are rewritten, while recorded groups must verify their SHA256 before
being skipped. The manifest binds the source-manifest digest, the recipe fields
`engram_bits`, `engram_group_size`, `keep_mtp`, and each group's entry-list digest.
Layer-only recipe amendments leave these bindings valid. Completed layers always
pass amendment-aware record validation; cached hashes require matching record
digest and each artifact's size, mtime_ns, inode, device and ctime_ns. A changed
signature triggers normal artifact verification. Both the layer part and its
statistics file are covered. Cache updates and group manifest updates are atomic;
independent locks serialize callers without taking the live run's model lock.

Staging and final output must share a filesystem: all tensor files are hardlinked,
so final assembly needs only small metadata space. Keep staged files and parts
immutable after linking. By default final assembly hashes staged files again;
`--trust-stage-hash` skips this only when their recorded size, mtime_ns, inode,
device and ctime_ns still match. A signature change falls back to SHA256; size,
source, bound recipe, entry-list or hash mismatches fail closed. The final artifact
inventory reuses those verified hashes rather than scanning staged tensors again.
The trust option assumes immutable local files and a trusted manifest/cache.
