# Main versus v0.12.18 performance spot check

## Result

No reproducible throughput or resident-memory regression was found across ten
cached text models spanning 0.6B through 35B. Using the best steady-state arm
to remove first-run Metal compilation and page-cache bias, main ranged from
1.9% slower to 4.6% faster than v0.12.18. Peak RSS changed by less than 0.4%
for every model.

This is a single-user, short-context decode spot check. It is not a concurrency,
long-context prefill, TTFT, image, audio, or power benchmark.

## Environment

- Date: 2026-08-23
- Host: Mac Studio `Mac15,14`, Apple M3 Ultra, 28 CPU cores, 256 GB memory
- OS: macOS 26.5.2 (25F84)
- Candidate: main `ba5025f1ac4a804e78417157e2e85530c0d3506f`
- Baseline: tag `v0.12.18`, `291ede85b8688e7f2c60601e70c8403f1221ccd4`
- Python: 3.12.13
- Candidate environment: MLX/Metal 0.32.1, mlx-lm 0.31.3,
  transformers 5.12.1
- Baseline environment: MLX/Metal 0.31.2, mlx-lm 0.31.3,
  transformers 5.12.1
- Models were already complete in the shared Hugging Face cache. No weights
  were downloaded.

Each checkout was installed into its own `uv` virtual environment. This keeps
the main dependency change to MLX 0.32.1 in scope instead of comparing only
Rapid-MLX source against one shared runtime.

## Method

For each model, run two samples per arm in ABBA order:

```text
main -> v0.12.18 -> v0.12.18 -> main
```

Each sample was a fresh process and used the same fixed command:

```bash
python -m vllm_mlx.cli bench MODEL \
  --num-prompts 3 \
  --max-tokens 256 \
  --max-num-seqs 1
```

The primary metric is reported `Throughput` in tokens/second. `best` is the
higher of each arm's two samples, matching the repository's A/B convention of
using the best arm to reduce cold Metal compilation and model page-cache bias.
Peak RSS came from `/usr/bin/time -lp`; the table reports the two-sample mean.
All 44 primary and confirmation invocations exited successfully and returned
non-empty completions.

## Interpretation and limitations

- Nine models are within approximately +/-2%; the 35B-A3B MoE improves by
  4.6%. There is no evidence of a release-blocking regression.
- Qwen3.5 4B had unusually high within-arm variance during the first ABBA pass.
  A reverse-order confirmation (`tag -> main -> main -> tag`) produced best
  results of 166.09 versus 162.90 tok/s, so the apparent initial improvement
  did not reproduce. Treat its -1.9% result as advisory.
- The first sample of several models paid visibly more cold compilation and
  filesystem-cache cost. Medians therefore penalized the arm that ran first;
  best steady-state results are the fair comparison for this small sample.
- Some models stopped before 256 tokens on one or more prompts. Their reported
  tok/s remains useful as a spot check, but short sequences include more fixed
  overhead. Models that completed all 768 requested tokens provide the cleanest
  evidence.
- A separate same-runtime control using MLX 0.31.2 for both checkouts put nine
  models between -1.1% and +0.2%, with RSS within +/-0.4%. That isolates the
  Rapid-MLX source diff and supports the conclusion that observed variation in
  the full-version comparison is predominantly runtime/cold-state noise.

## Recommendation

Treat current main as performance-ready relative to v0.12.18 for common B=1
short-context text decode. Keep the existing release gates for long-context
prefill, batching, tools, and multimodal paths; this spot check does not replace
them. If Qwen3.5 4B becomes a release headline model, repeat it on an otherwise
idle Studio with at least five counterbalanced samples per arm before publishing
a precise speed claim.
