## Implementation and contracts

- `scripts/deepseek_v41_streaming_teacher.py`: `calibrate` and `reference`
  entry points, `--tokens` per slice, header-only `--estimate-only`, default
  `--memory-limit-gib 180`, and `--logit-chunk 16`. Executes repository code
  only; never imports checkpoint Python. Reads the source index and bounded
  tensor ranges with the existing error-probe reader. Reuses `dequant.py`,
  converter sanitization, grouped-output reshaping, and native `Block` modules.
- `scripts/verify_deepseek_v41_streaming_teacher.py`: bounded, reproducible CPU
  comparison with a native resident forward over real dequantized weights.
- `tests/test_deepseek_v41_streaming_teacher.py`: independent whole-fixture
  converter comparison, all cross-layer state, sorted/unsorted expert prefill,
  score/cache contracts, chunked head and pre-read memory guard.
- Phase-2 report: corrected storage table, NVMe build destination, and complete
  later command sequence. No BF16 reference artifact prerequisite remains.

Execution is layer-major: embed every slice, release embed, load exactly one
BF16 decoder block, run every slice as a full causal prefill, evaluate surviving
arrays, release the block, then continue. Every sequence owns its hidden
`[1,T,hc,dim]`, staggered outgoing `pre_mix`, hashes and `SharedState`. The latter
retains the most recent compressed KV owner, index-key owner, per-query top-k
indices and candidate mask. Finished window caches are released; shared source
cache objects remain reachable until their consumers finish or sources replace
them. Cache arrays are explicitly evaluated before weight release, so deferred
graphs cannot retain previous blocks. No next-layer prefetch or full Model is
constructed by the streaming entry point.

Engram hash layout/history uses the original tokenizer map and native hasher.
Layers 1/14 retain original raw FP8 rows and UE8M0 scales. Unique row IDs per
slice are gathered from read-only source mappings, then dequantized in FP32
with `dequant_fp8_rows`; native Engram performs its usual input-dtype cast and
gated update. No affine Engram teacher or giant table tensor is created. Table
mappings are closed after gathering; no cross-slice row cache accumulates.
The token-map cache is written beside the output, never into the source.

Calibration observes native unweighted expert outputs once, preserving native
gate choices, selected unbiased gate normalization, multiplier, clamps, sorting,
FP32 routed accumulation and shared expert. Half membership is token position
within each original slice; slices retain independent state. Outputs include
`reap_halves`, MAN/MSAN means, routed counts by slice and half, domain maxima,
keep-set overlaps, source revision, tokenizer/config/corpus hashes, and existing
legacy aliases. The existing contrastive selector and allocator consume them
without changes. Unseen experts retain explicit zero counts, never invented
scores; coverage/protection/stability guards still apply.

Reference mode loads final norm/head only after freeing decoder blocks. The
head runs in bounded token chunks and writes **full-vocabulary FP32 logits** to
mmap `.npy` files with the existing tokens/mass/metadata/hash contract. Top-k
probabilities plus a full logsumexp cannot reconstruct exact full-vocabulary
KL against arbitrary candidates; no such approximation is used. Metadata is
written last, so partial caches cannot pass the existing comparator. Reference
and candidates run in separate processes. Candidate losses include their fixed
8-bit matrices and 4-bit Engram approximation relative to this source teacher.

## Faithfulness evidence

CPU-only MLX 0.32.4, MLX-LM 0.31.3, Python 3.13.15, NumPy 2.5.4. MLX CPU
GatherMM accepts F32 only. Both resident and streaming CPU checks use the same
local SwitchLinear adapter: promote matmul operands to F32 and restore each
projection's original output dtype. Metal uses unchanged native SwitchLinear.
BF16 source-dequantized weight values are preserved; no affine weights enter
the comparison. These checks prove scheduling/weight equality on CPU, not Metal
kernel equivalence or bitwise parity with quantized-activation checkpoint GEMMs.
Relative error denominator is `max(abs(reference), 1e-8)`.

| Comparison | Shape / coverage | Max absolute error | Max relative error |
| --- | --- | ---: | ---: |
| Synthetic hidden after every block, outgoing pre, final logits | 4 layers, dim 64, hc 4, 4 experts/top-2, two independent slices of 8/5 and 70/5 tokens | 0 | 0 |
| Real-source hidden after every block, outgoing pre, final logits | First 3 layers, dim 5120, full vocab 129280, first **8/384 experts** with top-6, two independent 4-token slices | 0 | 0 |
| Saved chunked-head logits versus native single prefill | Tiny source, 8 tokens, head chunks of 3 | 1.1920928955078125e-7 | 1.7497853832537658e-6 |

The tiny source contains FP4 experts, FP8 fixed weights and original FP8 Engram.
Its resident model is independently sanitized with the converter, rather than
assembled with the streaming layer loader. Sources/consumers cover ratio-2 and
ratio-1 compression, an index source that reuses another layer's keys, candidate
publication and consumption, staggered HC streams, Engram on layers 1/3, and
expert route sorting above 64 selections. The observer also preserves the
uninstrumented MoE output exactly. The tiny CLI cache self-comparison reports
zero KL/top-1 flips using the unchanged evaluator; cached logits are separately
checked against the normal resident forward.

The real check truncates **both depth and the expert axis**, preserving full
attention dimensions, native HC, original layer-1 Engram lookup and full head.
Router weight/bias/bias_vl rows and expert banks are restricted to IDs 0–7 in
both paths. This bounds the check; it does not qualify all 384 real experts,
layer 14 or the full real cross-layer sharing schedule. Those mechanisms are
covered synthetically; full-size Metal qualification remains outstanding.
Real CPU rerun: 22.73 seconds wall, including source reads and both schedules.
Sandbox restrictions prevented `/usr/bin/time -l` RSS counters; no measured
peak-memory claim is made. Detailed report/logs live in the permitted scratch
root under `phase3/real-faithfulness*`; the numbers and recipe are durable here.

## Memory, I/O and time planning

All sizes below are decimal GB. Estimates include an 8 GiB reserve and are
printed **before tensor-body reads**. The memory cap is in GiB. They model
resident layer, assembly, live sequence states and full-prefill temporaries;
they are planning allowances, not measured hardware limits.

| Planned workload | BF16 block | Stack assembly transient | Persistent sequence states | Prefill scratch allowance | Estimated peak incl. reserve |
| --- | ---: | ---: | ---: | ---: | ---: |
| Calibration: 36 × 8192 = 294912 tokens | 27.847 | 9.060 | 16.614 | 76.101 | **138.212 GB / 128.72 GiB** |
| Calibration fallback: 36 × 4096 | 27.847 | 9.060 | 7.703 | 29.461 | **82.661 GB / 76.98 GiB** |
| Reference: 38 × 512 = 19456 tokens | 27.847 | 9.060 | 0.947 | 2.743 | **49.186 GB / 45.81 GiB** |

The ~9.06 GB temporary is the largest expert stack while assembling a complete
layer; there is still only one decoder layer resident. Scratch includes query,
expert/HC intermediates and quadratic indexer scores. Token-count reductions
lower persistent state linearly and indexer scratch quadratically. Source Engram
rows and OS/device allocator behavior can vary; the 180 GiB cap leaves host
headroom on 256 GB hardware. Full-slice prefill avoids a second source pass,
but native sparse/indexer execution still needs real watchdog/memory checks.

Header accounting measures **298,624,579,008 sequential source bytes/pass**:
exclude vision/MTP and giant Engram tables, which are read by selected rows only.
At 0.9 GB/s this is **5.53 minutes I/O minimum**. Using the requested conservative
**475 GB/pass** allowance gives **8.80 minutes/pass**, or 17.59 minutes for
calibration plus reference. Cold Engram random reads can amplify page I/O and
lower effective throughput; neither number is a promised elapsed time. All
36/38 slices stay in their respective single pass: never multiply 475 GB by
slice count. Small extra token-map startup is cached beside the output.

Approximate active routed-expert arithmetic is 5.01 PFLOP for calibration and
0.3305 PFLOP for reference (`2 * tokens * 40 * 6 * 3 * 5120 * 2304`), before
attention/shared/head work. At an assumed effective 2–10 TFLOP/s this contributes
8.4–41.8 minutes and 0.55–2.75 minutes respectively. Serial source reading,
dequantization/stacking, FP32 HC/indexer work and random Engram reads add to it;
no throughput benchmark has been run. Reserve **30–90 minutes calibration** and
**15–45 minutes reference** as initial scheduling estimates, with substantial
uncertainty. At high effective GPU throughput the conservative ~9-minute read
floor can dominate; at these full token counts compute/dequantization may also
dominate. Per-layer elapsed seconds are printed to replace assumptions with
measured estimates on the owner run. No calibration/reference pass should be
launched per slice.
