# M3 Ultra MTP depth qualification

The implicit MTP maximum changes from 1 to 3 for GPU generation 15 / Ultra /
exactly 256 GiB, MLX 0.32.4 and macOS 26.5.2. The entry requires an installed
head, batch 1, MTP mode, family `qwen3_5_moe_text`, geometry
`(2048, 512, 256, 8, 4, 64)` and uniform affine expert quantization. Unknown
hardware, software and model facts retain their existing depth. Dense 4B/9B
models cannot select this row. Explicit JSON and environment priority, checkpoint
clamping, and the existing request-local acceptance controller are unchanged.
Cap 3 allows up to three drafts; it does not force three each round.

Measured source: `e99b6bb1bcdf950932826a3858f383621a243e64`; main baseline:
`bb6ea903645d65b14c231cd90e26d3b04cc55569`, 2026-11-10. Apple M3 Ultra,
256 GiB, Python 3.12.13, MLX 0.32.4, mlx-lm 0.31.3, mlx-vlm 0.7.2,
transformers 5.15.1. GPU core count is absent from device-info; the row pins
generation, tier and exact memory without inventing a core count. Other knobs
retain their existing defaults.

Cached target `mlx-community/Qwen3.6-35B-A3B-4bit`, revision
`38740b847e4cb78f352aba30aa41c76e08e6eb46`; cached head
`mlx-community/Qwen3.6-35B-A3B-MTP-4bit`, revision

Three interleaved fresh-server repetitions per arm, middle order reversed.
Excluded short warmup, 564 templated prompt tokens, 256 greedy output IDs,
thinking disabled. Client decode rate excludes TTFT and the first chunk. All
valid repetitions retained. Caps use the registered override and retain auto-K.

Cap 3 gains 8.83% over main MTP and 2.84% over local plain, with non-overlapping
ranges. Tokens/forward divides the 255 post-prefill output tokens by observed
target forwards. The unchanged default is raw-ID-identical to main in all three
pairs. Raised-depth width-dependent BF16 argmax differences are assessed by the
paired quality gate, rather than requiring identical IDs to one-row decode.

permits such width-dependent differences. No controller or arithmetic change is
introduced to conceal the variation.

## Dense MTP controls

Same source pair, prompt/output protocol and verified lock. Three interleaved
fresh-server pairs for 4B. The first three 9B pairs had a lower branch median,
so three additional pairs completed balanced main-first/branch-first ordering;
all six are retained below.

| Model | Pairs | Main median [range] | Branch median [range] | Median delta | Tokens/forward, both |
| --- | --- | --- | --- | --- | --- |
| 4B | 3 | 153.86 [152.73–155.31] | 153.02 [150.95–154.14] | -0.55% | 1.555 |
| 9B | 6 | 115.875 [111.61–116.64] | 113.16 [110.24–116.35] | -2.34% | 1.614 |

Every pair is raw-ID-identical, with identical tokens/forward. Timing ranges
overlap. The 9B paired timing sign-flip test gives two-sided p=0.09375; a small
throughput regression cannot be ruled out by these noisy samples. No claim of
zero timing cost is made. The new model-scoped table row cannot change either
dense model's depth, covered by headless tests.
