# v0.13.4-to-main release audit (2026-09-06)

## Scope

Vector and Harbor initially reviewed the complete first-parent release range
from tag `v0.13.4` through `18d488664` (`feat(desktop): add supervised
Downloads cleanup flow (#3231)`). Vector extended that review on 2026-09-08
through request-time `origin/main` at `e6f3d8896` (`feat(share): --quicksilver
compute-pool provider mode (#3251)`). The extended range contains 111 merged
pull requests, 439 changed files, and 89,573 additions / 2,039 deletions.

The inventory is reproducible with:

```bash
git fetch --tags --prune origin
git log --first-parent --pretty='%h %s' v0.13.4..e6f3d8896
git diff --stat v0.13.4..e6f3d8896
```

Review emphasis followed release risk rather than diff size:

- privileged persistent-service install, configuration, credentials, upgrade,
  restart, logging, and runtime supervision;
- Desktop resident-engine lifecycle, port allocation, workflow execution, and
  gated Computer Use surfaces;
- image model catalog/download/load paths and the release dogfood receipts;
- Qwen hybrid-cache, speculative decode, QSA, RMSNorm, and scheduler changes;
- public API/tool-call behavior, model admission, and release/benchmark gates;
- lower-risk documentation, presentation, and CI-only changes.

In addition to reading the merge commits and their tests, the range passed
`git diff --check` and `python3.12 -m compileall -q vllm_mlx scripts`. Added
Python/Swift/shell lines were scanned for subprocess execution, shell
evaluation, unsafe deserialization, privileged path mutation, public bind
addresses, credentials, forced casts/unwraps, and assertion-only production
guards. Swift forced casts and `try!` additions found by the scan were confined
to test fixtures.

## Release-blocking findings and fixes

Five P0/P1 findings survived adversarial review. Each fix is isolated in its
own PR and is fail-closed.

| Severity | Finding | Fix | Verification |
| --- | --- | --- | --- |
| P0 | A service account could pre-create `~/.rapid-mlx-secrets` as a symlink. Root-run `service credential set` followed it and could chmod/chown the target; `unset` could unlink a target file. | [#3179](https://github.com/raullenchai/Rapid-MLX/pull/3179) pins an `O_DIRECTORY|O_NOFOLLOW` directory fd and uses fd-relative create, replace, unlink, chmod, chown, fsync, and inode race checks. | Merged in `637bdc719`; 195 focused tests and exact-head hosted matrices passed before merge. The combined main service suite now passes 204/204. |
| P1 | Persistent `rapid-mlx service` configuration accepted wildcard, LAN, and DNS binds while authentication is optional, contradicting its loopback-only deployment contract. | [#3178](https://github.com/raullenchai/Rapid-MLX/pull/3178) accepts only `localhost`, IPv4 loopback (`127/8`), and IPv6 loopback (`::1`) for the persistent service. Ordinary foreground `rapid-mlx serve` remains unchanged. | Merged in `cbfc4c2cb`; 195 focused tests and exact-head hosted matrices passed before merge. The combined main service suite now passes 204/204. |
| P1 | The Desktop default moved from port 8000 to 7659 without a one-shot upgrade migration. Existing installations with no explicit stored port silently moved and disconnected clients configured for 8000. | [#3177](https://github.com/raullenchai/Rapid-MLX/pull/3177) preserves 8000 exactly once for existing installs, leaves fresh installs on 7659, and never overwrites an explicit port. | Merged in `d817e6538`; 15 focused Swift tests, full hosted Desktop build/tests, PR validation, and exact-head CI passed. |
| P1 | Draft-and-post visual recovery retained only host/port/bearer/model identity. A bearer that survived a server restart could authorize screenshot upload and a bounded click against a replacement server process. | [#3242](https://github.com/raullenchai/Rapid-MLX/pull/3242) requires a per-launch bearer and binds every retained visual runtime to the exact Desktop server session UUID. | Merged in `430974e56`; 33 focused Swift tests plus the combined candidate's Desktop build and all six GUI shards passed. |
| P1 | Root-run headless service qualification read the persistent API credential and sent it to whichever loopback process answered after bootstrap. A local bind race could receive that reusable secret. | [#3244](https://github.com/raullenchai/Rapid-MLX/pull/3244) qualifies a transient eager-start definition through model-resident readiness, then commits the requested lazy policy without reading or transmitting the credential. | Merged in `463ecd39e`; 217 focused service tests, 100% upgrade-module coverage, Python 3.10/3.11/3.12, Apple Silicon, five L1 model smokes, Ruff, mypy, and PR validation passed. |

A suspected service-definition parent-symlink issue was rejected after tracing
the real path: definitions ignore the service user's home and live under the
root-managed `/Library/Application Support/Rapid-MLX/Services`. This is not an
attacker-controlled parent and no fix PR is warranted.

## Image and performance release evidence

The ten built-in image aliases passed exact-wheel, real-weight dogfood on the
M3 Ultra. Desktop release-mode dogfood also covered real generation,
cancellation/recovery, editing, and clean quit. Commands, revisions, outputs,
and limitations are recorded in
`docs/engineering/operations/2026-09-06-image-release-candidate-dogfood.md`.
The source receipt predates the eventual final release commit, so the final
signed/notarized artifact still requires the artifact-level rerun described in
that document.

The image precision qualification harness in
[#3173](https://github.com/raullenchai/Rapid-MLX/pull/3173) passed 22,858 tests
(122 skipped, 22 deselected, 6 xfailed, 1 xpassed) locally and all exact-head
hosted checks; it is on main. Qwen3.5 4B MTP default-off dogfood in #3144 and
the other opt-in performance work preserve stock behavior unless explicitly
selected.

The MLA path from
[#3110](https://github.com/raullenchai/Rapid-MLX/pull/3110) is now on main and
remains explicit opt-in. Its measured GLM-4.7-Flash-4bit M=3 improvements are
2.500x at 1K, 6.594x at 4K, and 16.180x at 16K; the 4,457-token suffix case is
4.054x with stock/absorbed output length 128/128. Its attested family adapters
cover DeepSeek V3, GLM4 MoE Lite, Kimi Linear, and LongCat Flash.

## M3 release-gate result

`make release-check-m3` reached the following G0 coherence results on the
Studio host:

- Qwen3.5 4B: 6/6 pass
- Qwen3.6 27B: 6/6 pass
- Gemma 4 12B: 6/6 pass
- GPT-OSS 20B: 6/6 pass
- DeepSeek-R1 32B and HY3: capacity-skipped because of disk constraints
- Qwen3.5 35B-A3B 4-bit: infrastructure failure after 180 seconds without
  startup progress

The 35B failure was attributable to the cache storage available during that
historical run, not an alias mismatch or a demonstrated code regression. The
alias correctly resolves to `mlx-community/Qwen3.5-35B-A3B-4bit`. No model
cache was deleted. Studio storage policy changed on 2026-09-07: release checks
must now use only the configured Hugging Face cache, including its managed
warm-tier symlinks; they must not redirect downloads or access personal archive
volumes. The full gate remains pending under that policy, and a quota failure
must be reported rather than worked around.

## Release decision

All five P0/P1 fixes found by this audit (#3177, #3178, #3179, #3242, and
#3244) are on main. The reviewed source range is P0/P1-clean at `e6f3d8896`.
This source conclusion does not replace release acceptance: the final signed
and notarized candidate must rerun the artifact-level image receipt, and the
complete `release-check-m3` must finish under the current Studio storage
policy. Deleting shared model caches or redirecting model downloads is outside
this audit's authority.
